后续根因诊断与“Main 先定位再派工”候选验证见[第三轮报告](worker-directory-llm-validation-2026-11-14-r3.md)；本页保留 R2 当时的失败结果。

2026-11-14 完成预先安排的 10 次隔离真实 Main 验证，**不能确认这版说明改善了 cwd 选择**。原六个场景重测通过 3/6，上轮为 4/6；两个失败场景增加重复后，客户合同为 1/3、Atlas 模块为 0/3。全部十次通过 4/10，目录不明确的七次仅 1/7 通过。该小样本不能证明总体准确率变化，但足以拒绝“最小修改已稳定解决问题”的结论。

- Worker 真实启动原生引擎并加载规则，模型请求全部交给本地 Responses 并保持等待，避免完成事件再次触发付费 Main。只验证 Main 的选择与实际原生上下文，不验证真实 Worker 的后续解题效果。
- 十次原生 Main 历史均包含本次新目录规则；十次 Worker 实际 cwd 均与宿主接受值一致。失败不能归于旧 Main 提示未采用，或宿主没有传递选择值。

## 原因判断

已证实的问题有两种：

1. **客户案例仍过早结束定位。**两次查看相关分支后选择客户根，只加载客户规则；第三次继续定位后选到了合同文件目录，说明目录、文件工具和原生继承能够工作，但模型执行不稳定。
2. **项目案例把定位工作留给 Worker。**Atlas 三次、账簿助手一次均直接在 `Main` 派工。若干失败样本的派工消息包含定位项目／文件的要求，记录中保留了这一事实的布尔特征，没有保存原文。Worker 从默认目录启动时，没有自动获得目标分支规则。

合理推断是，“工作入口已知”“默认适用”的边界仍可被宽泛理解：知道项目名称，或者认为 Worker 可以自行寻找，就直接派工。工具说明只有被发现／查看时才能帮助决策，无法替代 Main 在派工前承担定位责任。这是待验证的解释，不是从十例推导出的唯一因果结论。

下一步最小文字方向是明确：**依赖本机现有资料的任务，由 Main 在派工前确认任务范围对应的实际绝对目录；知道项目名、让 Worker 再去找，都不算目录已经明确。默认目录只用于确实适用的任务。**任务限定子目录的选择规则继续保留。本轮没有再次修改产品提示词或工具说明，也没有增加扫描逻辑或接口。

## 复验入口与收尾

保留显式入口 [worker-directory-llm-validation.mjs](../scripts/worker-directory-llm-validation.mjs)。它不进入默认测试，缺少模式和配置会拒绝执行；私有运行目录必须为空且位于本项目 `.codex/private/`，源码及指标目录须位于 `.codex/scratch/`。

配置只保存本机路径，放在忽略目录，格式如下；`--self-check` 不读取认证文件、不调用付费模型，`--paid` 必须有当轮授权。所有目录使用任务独占路径。

```json
{
  "source": "/absolute/repo/.codex/scratch/source-snapshot",
  "privateRoot": "/absolute/repo/.codex/private/directory-validation",
  "reportDirectory": "/absolute/repo/.codex/scratch/directory-evidence",
  "codexBin": "/absolute/path/to/pinned/codex",
  "authFile": "/absolute/path/to/authorized/auth.json",
  "dailyProfile": "/absolute/path/to/desktop-profile.json"
}
```

先按上述基线构造快照、只叠加两处文字，并在快照目录构建服务。使用 Node 22.22.0 执行以下两种模式之一；每次都需新建空的私有运行目录。

```sh
node scripts/worker-directory-llm-validation.mjs --self-check /absolute/path/to/spec.json
# 仅限已获本轮付费授权：
node scripts/worker-directory-llm-validation.mjs --paid /absolute/path/to/spec.json
```

脚本语法与原生隔离自检完成；重复使用非空私有目录会在启动引擎前拒绝。指标校验完成后，确认所有本任务宿主及原生进程停止，再删除独立认证状态、原生历史、数据库、源码快照和合成 home，只保留入口、报告及脱敏结构化证据。未提交、推送、部署或操作日常 Homer runtime。
