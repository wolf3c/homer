# 产品定义

## 1. 产品目标

用户通过文字或口述交代目标，荷马负责理解、组织、执行和交付；用户无需理解模型、引擎、MCP、Skills 或底层任务配置。

成功体验是「交代后事情有着落」：进展清楚，成果可用，需要协助时容易处理，失败时有明确说明。

## 2. 已确认的方向

- 一个主 Agent 作为主要入口，不要求用户自行组织多个伙伴。
- 主 Agent 可以定制并派发执行任务，管理清晰的事项清单。
- 独立开发最小产品，借鉴 Cindy，而非直接维护完整 Cindy 分叉。
- 使用 Codex 单引擎，通过 App Server 集成。
- 利用现成工具和生态提供能力，在其上开发自己的产品。
- 首版不提供图形界面，通过命令行发送消息完成对话测试；后续优先通过 IM 提供入口，暂不建设自有 App。
- 工作名为「荷马 Homer」，Logo 形象使用河马；正式品牌存在重名待核查。

## 3. 用户与首发场景

长期面向不愿研究技术配置、希望直接委托工作的非技术用户。

首发细分客户尚未确定。咨询／培训工作室、独立知识工作者、内容团队均为候选，不属于已验证市场。

首版建议验证：资料研究与文档交付、材料整理。暂不承诺可以无人值守完成所有网站和桌面应用中的任意工作。

## 4. 交互原则

1. 主伙伴统一接待；复杂事项在后台隔离上下文，首版不要求用户打开独立界面。消息通过事项名称、必要的短标识及明确引用保持归属。
2. 事项由系统创建和维护，不让用户学习项目管理；用户仍可查看、纠正和停止。
3. 用户不需要选择模型或引擎，费用与执行限制由产品后台管理。
4. 简单回答直接完成；需要独立执行、等待或并行时才派发任务。
5. 指代不清时确认归属，不能猜测并修改另一事项。
6. 对外声明完成必须有成果或可验证回执；执行结束不等于用户目标已达成。
7. 能力配置由系统承担；身份验证和超出既有授权的动作应有简短、具体的协助入口。

## 5. 长期能力目标

| 编号 | 用户要求 | 说明 |
| --- | --- | --- |
| C1 | 电脑和浏览器操作 | 锁屏仍能工作是期望，需要区分本机桌面、后台浏览器与远程环境 |
| C2 | 高自主性授权与配置 | 在明确委托范围内自行处理登录、工具配置等，减少逐步确认；不能假定验证码、生物识别可全自动完成 |
| C3 | 手机通知与人工协助 | 遇到确认或障碍时手机处理，再继续原任务 |
| C4 | Office 文档处理 | 读取、生成与修改，按明确格式范围逐步扩展 |
| C5 | 丰富且可扩展的能力生态 | 搜索、安装、连接、验证及维护所需工具、Skills、MCP |

以上是产品目标，不是首版全部交付承诺；阶段划分见 [需求与首版范围](02-requirements-and-mvp.md)。

## 6. 首版明确不做的方向（建议）

不建设自有图形界面、网页聊天页或原生 App；不向用户开放多引擎配置；不做用户手动创建伙伴及伙伴群；不建设通用流程设计器；不一次覆盖全部桌面应用；不自行训练模型；不重建成熟工具已有的底层能力。
