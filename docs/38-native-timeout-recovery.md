## 行为与兼容

主 Agent 不再有 Homer 累计执行 deadline。Worker 与递归子任务也不再由 `timeoutMs` 自动获得两分钟共享预算；派工、领取、继续和接管不再因累计耗时拒绝。Codex 继续拥有原生执行、网络流空闲检测和重试；Homer 未添加看门狗、循环检测或自动请求重试。

`timeoutMs`、`mainTimeoutMs` 仍可读取旧 JSON，数字存在时保留原有合法值校验，旧 null 与缺省均作为未设置处理；不再默认注入或用于执行、审批和刷新。旧 `authorityJson.maxActiveMs`、`runs.activeMs` 和 `usedBudget/charge` 历史读取及计时保留，耗时不再是执行授权边界。模型工具原本不接收预算字段，仍不能借此新增授权。根任务不再生成 maxActiveMs；子任务可携带历史原值，语义仅为历史记录。旧迁移的零预算可能与来源缺失同时存在：移除计时限制后，派工、领取和接管直接校验既有 trustedSource，来源缺失仍拒绝；不能用旧零值取消来扩大授权。无需 schema 升级、批量改库或删除旧字段；旧 failed/timeout、待验收、cancelled/uncertain、来源、停止 fence 和未知操作回执不改写。

保留独立等待：本地引擎 initialize 握手15秒、工具安装/配置审批540秒、能力采用轮询30秒、`stopGraceMs` 停止确认。普通RPC已随[RPC生命周期修复](38-native-rpc-lifecycle.md)取消统一15秒截断，由原生响应或通道关闭结算。原生权限审批继续走已有 owner 和真实用户收据。本次未更改权限、附件、渠道发送或记忆策略。维护脚本的 130 秒结果观察窗口只停止观察，不中断或重试实际请求。

## 接待恢复

- 已确认的普通 failed turn 或空正文失败：保留失败记录，健康进程继续接待新输入；内部事件允许空正文，正式交付仍使用已有事实兜底。
- 进程不再可用或执行 promise 未确认结束：先 close 并确认停止。仅在原生后台活动已解决、原 thread 可恢复时标记 `main_recovery_ready`。后续队列作业才重建，不重放失败用户请求。
- 重建使用原 runtime 绑定、同一账号/供应配置、持久 mainThread、当前 mainWorkingDirectory 和重新读取的附加指令。新旧 thread 不一致即失败，不创建替代会话。
- 图片能力查询在统一主轮恢复和能力刷新之后执行，避免首条图片输入探测已经失效的旧进程。真实来源、附件接收与 requestId 防重仍先走原入口。
- 停止未确认、后台活动未解决或原 thread 不可恢复：普通服务重启恢复原 thread 时同样检查原生后台忙碌状态，保持模型执行入口关闭；记录 `main_recovery_blocked` 及稳定原因，失败答复明确未启动替代执行，并拒绝后续模型执行。不得以改 thread/清 lease/重派操作绕过；需核对原进程和原生终端后沿既有维护路径处理。
- 恢复启动失败保留原 thread 和失败事实；只在关闭及恢复条件仍可确认时允许下一条新请求再次尝试接待恢复。未自动继续任何失败或未知业务操作，不增加发布、重发或重派任务。
