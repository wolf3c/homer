# 本地 Git 与开发工作区

Homer 使用一个本地 Git 仓库维护源码、测试、产品素材、项目 Skill 和维护文档。初始提交保存接入 Git 时的实际源码状态，不代表尚未整合的候选或全部真实链路已经验收。没有自动创建远程仓库或上传。

## 开发与审阅

- 简单修改直接在主工作目录完成；先查看 `git status`，保留其他人的未提交工作。
- 需要并行隔离时，按实际任务使用独立分支和 `git worktree`；不为每个小任务复制整个项目。
- 新 worktree 基于明确提交建立。依赖和公开大资源可按已有只读复用方式处理，不能复制账号、运行库和私有配置。
- 每项变更先检查 diff、运行相关验证，再按既有授权提交和整合。Git 提交不等于日常服务已采用。
- 主 Agent 提示词的修改仍须先展示准确 diff，由用户确认；Git 不改变原有审阅和安全空闲更新边界。

## 数据与产物

`.codex/private/`、`.codex/scratch/`、依赖、构建输出、凭据、数据库及本机临时文件不纳入版本管理。产品源码中的 API key 仅保留环境变量名。

Git 不能自动回收测试产物。任务完成后需要核对：候选已审阅整合、必要验证已完成、没有任务/进程/运行配置继续引用工作目录；保留准确补丁、基线、采用和回退证据后，才移除过期测试数据及工作副本。

- 尚未整合的候选继续保留，即使执行任务显示结束。
- 旧复制副本按上述条件逐项收尾，不批量删除 `.codex/scratch/`。
- Git worktree 应使用 `git worktree remove <路径>` 正常移除；存在未提交修改时先处理，不使用强制删除。
- Cindy 中关闭临时项目与删除文件是两件事：通过宿主管理工具归档已完成任务、隐藏临时项目；保留任务历史，不修改宿主数据库。
- 正在运行的任务不迁目录、不停止；完成后再整合和清理。
