# Worker 目录上下文 v0.8 实施计划

依据：[v0.8 方案](../specs/2026-11-12-worker-directory-context-design.md)。授权：实施、复审、离线检查、固定版本原生隔离验证及本次本地提交；不推送、部署或调用付费 LLM。

## 完成条件

- Main 按需调用只读 `list_work_directories({})`；复用宿主 MCP，不向 Worker 注册。
- 只发现五类位置特征，按一级目录压缩；不读正文、不建立索引、不注入每条输入、不新增容量裁剪。
- 查询有截止时间和 Main 轮次有效性检查，部分失败明确返回；路径控制字符不能伪造树结构。
- `work_directory`、`worker_open` 动态声明和 `MAIN_TOOLS_HASH` 不变。
- Worker 每次冷初始化从原生配置取得根标记，保留既有标记和 `.git`，追加 `.homer-project-root`；仅确需主目录兜底时准备该空文件，最终原生配置在其后加载。
- 新旧线程在合成目录和隔离 HOME/CODEX_HOME/runtime 中验证；真实用户主目录与日常 Homer 数据不变。

## 任务与检查

1. **目录发现与根准备**：新增两个小模块及行为测试。目录发现依赖系统目录事实、已知 cwd 和查询存活检查；根准备依赖真实主目录与原生生效标记。先观察测试失败，再实现。覆盖排除区、隐藏标记、链接、控制字符、空结果、部分失败、过期；根覆盖 Git、自定义、无 Git 多层继承准备、冲突及主目录外行为。
2. **宿主接线**：Main MCP 注册和只读路由；短提示说明语义选择与按需查询。Worker 引擎冷启动回调复用配置控制连接读取原生标记；最终配置验证标记未丢失。验证角色权限、无目录选择副作用、旧会话恢复、初始化失败与关闭竞态。
3. **专项验收**：注册显式 `directory-native` 套件。使用固定 Codex 0.163.0、全新合成目录和本地合成 Responses 服务，检查新建/恢复、Main MCP、根继承和配置信任；不使用真实账号或外部模型。
4. **收尾**：Node 22.22.0 类型检查、相关离线回归与默认完整离线套件；独立最终评审。更新架构正文、索引及测试说明，只带回本任务改动并清理临时副本。

## 接口与边界

目录发现返回 `{directoryReference, complete, issues?}`。系统目录事实为内部可注入依赖，模型接口仍为空对象。发现结果不是授权或合法 cwd 白名单。工具错误使用现有 MCP 错误处理。

Worker 根准备只返回原生启动覆盖值，不解析指令正文或 TOML，不改变信任与文件权限。配置控制连接不执行模型轮。Main 不应用主目录兜底覆盖。

实现先在忽略的普通源码副本中验证，避免并行脏工作树与日常运行受影响；集成时按基线逐段应用，不创建 Git 分支或工作树元数据。`work_directory` 与动态声明做字节比较。付费 LLM 的目录选择效果、Windows 原生行为另行验收。
