# 对话气泡事项标题打开 Preview 的实施方案

2026 年 11 月 25 日。用户已通过合成 Demo，并批准按独立复审结论实施。

## 用户看到的行为

- 主对话里，已有事项标题左侧使用 `ListTodo` 线形图标，沿用定时任务标题 `Clock3` 的图标尺寸、边距和标题密度。使用 Demo 的 15 px 图标与 12 px / 18 px 标题字号和行高。可打开的标题带下划线，图标和标题组成一个按钮。
- 点击标题或图标打开同一事项的 Preview，落点与工作状态列表点击该事项一致。再次点击同一个事项复用已打开的标签。一次回复涉及多个事项时，逐个显示可独立操作的标题，间隔沿用 `、`。
- 既有标题顺序、同事项连续回复的折叠规则及原文入口照旧。未能核实归属的标题用普通文本呈现。已归档但仍可通过详情入口访问的事项支持打开。

## 1. 沿用可信事项身份

- [x] 从 [主对话消息标题投影](../../../ui/homer-app.tsx) 入手。在 `messageTaskTitles` 的现有条目上附上可选的已核实 `taskId`，保留现有显示键与标题。`message.taskSources` 保留现有标题来源。[服务端 `withTaskSources`](../../../src/web-homer.ts) 对可打开的来源另做精确校验。旧回执或操作仍能展示标题，缺少同轮证据时只显示文本。来源里的 `version` 用于服务端核对消息归属，打开 Preview 时沿用现有的 `taskId`。
- [x] Worker 事件仍走现有标题回退分支。主对话保持现有 `includeCoveredSources` 模式。仅给已展示的事件补身份，按事件在该消息内的条目标识附加校验结果。回复按 `sourceMessageId` 对应同轮已接收回执及确认的 Worker 回复操作。交办按 `operationKey` 对应同会话、同轮、同输入的已确认 `worker_open`。两者都核对事项 ID、版本和运行身份。缺失或冲突时该标题保持文本，与其他已核实标题独立。
- [x] 继续用现有 Map 保持顺序与去重。已核实的同一 `taskId` 在同条消息内只出现一次，保留首个展示位置。同名但 ID 不同的事项独立显示。无法核实的条目沿用原显示键。同显示键只取首条，后续条目不改变首条的交互能力。保留 `singleReplyTask`、`continuesReplyTask` 的现有分组条件，比较值仍为原显示键与标题，避免回调或来源版本变化影响分组。

## 2. 接入现有事项 Preview

- [x] 工作状态列表和主对话共用 [现有事项 Preview 打开路径](../../../ui/homer-app.tsx)。入口依赖完整概览对象时，只把共享动作提取到 `taskId` 这一层。优先按 ID 激活已有标签并更新焦点触发元素。工作状态继续传现有摘要；消息无摘要时通过连接客户端读取 `/api/tasks/:id/summary`，核对 `overview.id`。仅当前线程、读取世代和最新打开意图可以应用读取结果，失败用聊天现有状态区域提示。异步网页打开共用已有 Preview 请求世代，接口仅准备页面，由仍有效的请求激活标签。
- [x] 当前消息、旧消息和归档消息使用同一身份规则。归档或移出工作状态的事项由已有详情权限和可达性判定。如果服务端在打开时拒绝访问或找不到事项，复用当前 Preview 的对应反馈。历史消息缺少已核实身份时保持标题文本，无需回填旧记录。

## 3. 在两处现有标题位置复用同一渲染

- [x] 在 [主对话消息组件](../../../ui/homer-app.tsx) 中让 `AssistantMessage` 的前置、后置标题共用一个小型渲染片段，保留相对于 `ProcessMessageContent` 的原有位置。在主对话列表提供打开回调。事项详情内的 `TaskMessageRows` 继续复用气泡组件，标题维持现有呈现，避免在当前事项里重复提供入口。
- [x] 使用原生 `button type="button"`。按钮名称包含完整标题，装饰图标从可访问树隐藏。Tab 按显示顺序进入各按钮，Enter 和 Space 打开，保留清晰的可见焦点。隐去的连续标题不可成为 Tab 停靠点。窄屏保留标题换行和图标对齐，打开后沿用 Preview 焦点处理，返回时优先恢复到原触发按钮，原按钮已卸载或折叠时回到现有 Preview 顶栏入口。
- [x] 只在已有标题行和样式中加必要的按钮规则。正文、引用原文、附件及定时任务各自保留现有独立点击目标。沿用已有图标库、消息来源和 Preview 数据结构，无需新增任务实体、IPC、独立路由、依赖或数据库变更。

## 4. 定向验收

| 场景 | 通过标准 |
| --- | --- |
| 当前、旧版来源及归档 | 经校验的版本打开正确 `taskId`。事项无须出现在当前工作状态列表。详情权限和读取错误由现有入口处理。 |
| 部分可核实与缺失身份 | 混合消息中仅已核实标题可操作。跨线程、缺失或冲突引用只能显示文本。 |
| 重复与多事项 | 单事项重复来源仅显示一次，多个同名事项分别打开正确的 Preview。连续回复的隐藏规则及跨日期与完成边界保持原表现。 |
| 两个入口 | 同一事项从列表及气泡打开时复用同一标签，快速切换时旧读取不会覆盖当前事项。 |
| 交互 | 核验两种标题位置、鼠标图标与标题命中、Tab 顺序、Enter、Space、可见焦点、窄屏返回及引用原文点击。 |
| 尺寸 | 用现有浏览器用例覆盖 Demo 的 1440、390、320 px 及 699／700 px 模态切换，包含长标题和并排时的 300 px 工作状态栏，并留代表性截图。 |

- [x] 离线检查沿用 [消息时间与分组](../../../tests/chat-timestamps.test.ts)、[会话投影](../../../tests/conversation-projection.test.ts)、[事项来源](../../../tests/taskcard-sources.test.ts) 和 [工作状态路由](../../../tests/task-overview-web.test.ts) 用例。只在现有断言无法覆盖新交互或身份边界时添加最小回归用例。
- [x] 浏览器检查沿用 [事项对话专项](../../../tests/task-conversation.browser.mjs)。关闭 Preview 后实际检查焦点落点，验证原文入口与事项按钮各触发一次预期动作。记录断言、退出状态及截图。安装版与真机验证按实际授权安排，分别记录状态。

## 实施与验证记录

- Node 22.22.0 源码类型检查、Web 构建及消息标题、事项来源、工作状态路由与 Preview 宿主合成回归共 50 项通过。额外运行会话投影回归时，定时来源文案断言在本次候选和 `d282d2d8` 基线均期望“定时消息”、收到“定时任务”。本事项保留该断言与行为。
- 隔离 Chrome 99 项通过，进程退出码 0，未触发 teardown watchdog。检查了 1440／390／320 px、699／700 px 切换与 300 px 工作状态栏，以及活动／归档入口、回焦、原文跳转、摘要身份错误和迟到结果。通过合成桌面桥验证网页列表通知先于打开响应时的标签激活。
- 独立代码复审收紧了旧来源导航、Worker 回报载荷和异步 Preview 守卫。真实 Electron 弹窗与挂起的事项摘要交错、安装版及手机真机不在本次验收范围。
