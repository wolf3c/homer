# 工作状态侧栏实施方案

**状态**　300 CSS px 栏宽和 700 CSS px 三栏下限已确认。已接入正式源码。隔离 Chrome 和 macOS Electron 验证见文末。

**目标**　可用宽度达到 700 CSS px 时，主对话、工作状态和 Preview 可同时显示。工作状态固定 300 CSS px，开关 Preview 或拖动分隔线都不会改变工作状态的展开选择。

**实现结构**　沿用 `HomerApp` 的 `react-resizable-panels` 双面板。左 Panel 内仍是对话和工作状态，右 Panel 仍承载 `CanvasPanel`。复用 `TaskStatusPopover` 的入口、`TaskList`、Portal 和窄屏 Popover，复用 Preview 的标签、Dialog 与原生边界同步。把侧栏展开值移到已持有 Preview 状态的 `HomerApp`，供同一个分隔线计算左 Panel 下限。改动在现有 React、TypeScript 和 CSS 内完成。

## 布局合同

| 外层工作区可用宽度 | 工作状态 | Preview |
| --- | --- | --- |
| ≥700 CSS px | 初始展开，固定 300 CSS px。用原入口收起或展开。按事项引用定位时，沿原路径显式打开并聚焦命中行。 | 按需显示右侧非模态分栏。开启、收起和拖动均保留工作状态的展开选择。 |
| <700 CSS px | 原有窄屏 Popover，默认关闭，按原入口打开。其开关独立于桌面展开值。 | 保留原有全屏模态、遮罩、键盘和触屏返回。退出时回到原触发点或既有目标。 |

外层宽度以 `Group` 容器的 `clientWidth` 为准。它覆盖对话、工作状态和 Preview 的共同可用空间。系统屏幕分辨率、Preview 分割后的左 Panel 宽度和触屏检测均无需参与判定。移动 WebView 与桌面窄窗采用同一条断点，触屏热区与安全区沿原 CSS。

合成 Demo 在 1024、768、700px 的实际宽度依次为 **376 / 300 / 347**、**243 / 300 / 224**、**207 / 300 / 192px**，顺序是主对话、工作状态、Preview，各加 1px 分隔线。700px 只有 399px 分给主对话和 Preview，需要正文换行和局部滚动。以上是已确认原型的呈现参考。产品沿用现有分隔线比例与拖动，初始像素分配由面板约束决定。

## 最小实施步骤

- [x] **在现有浏览器专项中锁定新行为。** 修改 [工作状态布局回归](../../../tests/task-status-pinned.browser.mjs) 的 `pinnedStatus` 和其滚动检查。替换 1119／1120px 旧门槛与 1440px 打开 Preview 后应出现浮层的旧断言。断言 699／700px 两边、768、1024、1440px 以及 390／320px 回退。保留角标、同一列表读取、防重复请求、待核实、分页和归档现有断言。先用隔离基线运行新增场景，确认旧实现因布局断言失败。
- [x] **由外层拥有宽度和侧栏展开。** 在 [HomerApp](../../../ui/homer-app.tsx) 用 `Group.elementRef` 和一个 `ResizeObserver` 读取外层宽度。复用一个 `narrowPreview` 布尔值传给 [CanvasPanel](../../../ui/canvas-panel.tsx) 与 [TaskStatusPopover](../../../ui/task-status.tsx)。`CanvasPanel` 删除内部 800px 布局判断，直接消费该值；`TaskStatusPopover` 删除 1120px 左栏观察与本地 `pinned`，接收应用层展开值和变更回调，窄屏 `popupOpen` 保留在原处。用于分隔线的侧栏占宽直接由宽屏模式、`taskOverview` 能力及同一展开值派生。通过 `aria-expanded` 和现有 Portal 保持入口与内容一致。首次测量和跨断点更新走现有阅读锚点通路，避免先绘制一个错误布局再跳变。
- [x] **限制现有分隔线。** [工作状态 CSS](../../../ui/task-status.css) 给非空插槽固定 300px（含边框），空插槽仍折叠。浏览器分栏时用库现有像素 `minSize`，左侧最小值为 200px 对话加当前侧栏占宽，右侧为 180px。工作状态收起后，原生标题栏保留 240px 左侧下限，以容纳系统按钮和顶栏入口。700px 有 19px 可分配给任一侧（700−300−200−180−1）。分栏改用这组像素下限，移除与之重叠的旧 25% 下限及桌面 75% 上限。库按外层宽度换算百分比后还需扣 1px 分隔线，因此传入的像素下限各加 1px，按实际面板矩形验收 200／180px。验证库对默认比例、容器缩放和动态 `minSize` 的约束；拖动和键盘继续使用原 `Separator`。宽度改变时保持合法布局，并保留现有比例中仍可用的部分。展开侧栏时仅将分隔线推回必要的合法区间。移位前复用 `captureAnchor`，后续重排由主对话原锚点逻辑处理。
- [x] **让全屏、滚动与焦点跟随同一模式。** 在 [Preview CSS](../../../ui/canvas-panel.css) 仅把全屏定位、遮罩、分隔线隐藏与全屏提示改为消费同一模式标记。800px 的 44px 触屏热区与原生标题栏避让作为独立样式继续生效。复用 `.thread-viewport`、`.status-list`、Preview 阅读器内滚动。按面板宽度缩减左右留白，保留正文字号和键盘滚动；长内容在所在面板换行或沿原局部滚动，标签继续横滚，关闭等常驻操作保留可点击面积。主对话按实际列宽收窄边距，让附件和右侧按钮组换行。Composer 引用与附件卡片按自身横滚条限宽，保留移除按钮。Preview 按面板宽度调整工具区，180px 边界下将网站身份、导航和操作分行，允许原按钮组继续换行；保留标题栏避让和原点击热区。
- [x] **沿用原开启、定位与返回路径。** Preview 缩放跨过 700px 时保持 `canvasOpen`、活动标签与草稿，同一 Preview 在两种布局间切换。进入全屏时关闭已有工作状态 Popover，将焦点交给 Preview 的活动标签或关闭按钮；放宽后保留 Preview 内焦点，不自动聚焦工作状态。工作状态跨形态时沿用现有条件回焦，仅当焦点原在消失的列表中且没有全屏 Preview 接管时回顶栏入口。打开事项 Preview 时，分栏保留原行作为返回点，窄屏使用顶栏入口；按引用定位仍由 `TaskList` 完成。侧栏展开选择不因进出全屏而重置。主输入、事项草稿、排队草稿与批注作用域沿原 owner，避免以模式为 key 重挂载。列表切换载体沿原加载语义，检查浏览期间列表无重复挂载或额外轮询。
- [x] **删除被布局规则取代的补偿，保留原生边界。** 分栏中的工作状态是普通布局元素，窄屏工作状态与全屏 Preview 不同时可见。验证这两条后，删除工作状态专用的 215px 局部浮层测量、`splitPreview` 参数及对应浮层标记。保留主对话引用编辑器和选区工具条的分栏边界，以及 `BrowserPreview` 的 WebContentsView 边界同步、模态让位及身份检查。真实网页、本地 HTML 按原占位更新 bounds，穿过 700px 时由同一个活动页继续展示，设置等模态关闭后按原规则恢复网页。沿 [原生浮层契约](../../architecture/preview-architecture.md#原生网页与宿主浮层2026-11-24) 核对。
