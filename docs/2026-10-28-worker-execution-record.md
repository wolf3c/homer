# Worker 执行记录

本次为本地源码实现。执行记录在原工作状态卡底部，默认收起；普通刷新保留用户选择，准确任务、版本、Run 或连接身份变化后重置。展开才读取执行资料和近期调用，逐条展开才读取安全正文。复用固定官方 RunActivity、ToolFallback 和 Base UI，不增加聊天 runtime 或依赖。

## 读取与准确性

- 执行状态、历史错误码、停止请求、替换来源和时间沿原任务详情 SELECT；活跃时长是已记录快照，与开始至结束的墙钟跨度分别标注。结果验收、正式交付与调用成功各沿原 owner，不互相推断。
- 现有 WorkerProgressStore 同时持有短期调用事实。身份包含 task/version/run/epoch/thread/turn 与真实原生 item ID 或宿主 call ID；同名不同调用独立，同一调用合并开始与结束，乱序开始不把终结改回运行中，缺字段的结束重放不抹去已留存结果，冲突终结标为待核实。
- 原生终结可晚于原 turn；同 thread 的迟到事件只补全已留存且 epoch 匹配的调用，不新增调用、工作或权限。主 Agent 的原事件过滤与宿主去重保持原逻辑。
- 新 GET 路径为 `/api/tasks/:root/execution/:task/:run`、`/before/:cursor` 和 `/calls/:key`，沿原 loopback、禁止 query、no-store 与有界读取机制。宿主取得可信主身份和当前主线程后，校验任务读取权限、root/task/run 关系和准确版本的 conversation_inputs 来源；不调用会生成验收证据的 inspect。
- 服务能力 `workerExecution:1` 缺失或读取源不可用时明确说明；断连显示上次记录，不表示实时执行。浏览器取消过期请求，并校验 selector、版本和 store generation；权限拒绝停止自动重读，允许用户明确重新展开核对。

## 留存与内容

只保存在进程内，不增加数据库表或持久日志，不从旧聊天、摘要或原生会话补造历史。服务重启、run 淘汰或未采集前的记录均可能缺失，界面始终说明历史不完整。

每个 Run 最多 128 条调用、正文最多 512 KiB；总计最多 256 个 Run、正文最多 16 MiB。每页 20 条终结调用，保留的未终结调用单独返回，避免被分页隐藏；游标绑定读取范围和进程 generation。超限先淘汰已终结调用或正文，明确标注省略。

正文留存前只允许固定字段：命令首个可安全识别的程序名、退出码，文件数量，以及已知宿主工具的机器状态、错误码和数量。原始参数、stdout、文件内容、查询、URL、任意 MCP JSON 不进入 Worker 记录。缺失、隐藏、截断与淘汰分别呈现；独立 exitCode 和 0 值不依赖输出正文存在。原主 Agent 的授权调用内容合同仅修复无 stdout 时的 exitCode 捕获。
