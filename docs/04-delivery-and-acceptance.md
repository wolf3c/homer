# 实施与验收

## 1. 当前目标与完成定义

从零先做 M0：CLI 发消息 → 主 Agent 建立事项并派发一个独立任务 → 读取指定测试材料、生成 Markdown → 核验、保存、回传 → 完成后的追问或修订。

M0 不以 IM、浏览器、Office 或任意插件安装作为前置条件。多任务并行及 Worker 授权／业务提问按用户后续要求纳入。范围对应 [需求 M01–M09](02-requirements-and-mvp.md)。

完成是可以按说明启动并运行的产品代码，加实际 Codex 端到端证据；仅写提示词、模拟输出或完成单元测试均不算完成。实施与自动化测试已完成，实际通过与限制以 [验证记录](07-m0-validation.md) 为准。

## 2. 实施假设与边界

- 先在当前 Mac 上本机单用户验证，固定模型；这是已采用的 M0 环境，不推定未来只支持 Mac。
- 已采用 TypeScript + Node 22.22.0 + 内置 SQLite；Codex App Server 直接通过 stdio 接入；当前本机入口为官方稳定 0.163.0 / gpt-6.1-sol medium，早期证据保留原版本标记。
- 沿用已经授权且适合本次开发测试的模型连接，不读取或复制其他产品的凭据，不自动购买、登录或变更账号。
- 用户已批准 M0，授权代码实现、正常依赖安装和沿用本任务连接的必要真实 Codex 测试，不再受此前仅整理计划的限制。
- 不建立独立服务、不接 IM、不初始化 Git 或提交代码，除非另有明确授权。

## 3. 实施步骤与逐步验收

| 顺序 | 工作 | 交付与通过门槛 | 依赖 |
| --- | --- | --- | --- |
| S1 | 核实运行环境与 App Server 接口 | 记录实际版本、启动与握手、线程创建／继续、工具调用、终止及事件接口；明确鉴权与可调用模型 | 无 |
| S2 | CLI 连通主 Agent | 自然语言多轮输入有真实响应；能恢复记录中的主会话关联；引擎错误显示明确 | S1 |
| S3 | 最小事项与执行存储 | 事项、执行、线程关联、状态转移可读回；重复请求不会重复建立同一次执行 | S2 |
| S4 | 派发并运行一个独立任务 | 主 Agent 经工具派活，Worker 有独立上下文；读取指定样例并写真实 Markdown；同时可查询进度 | S3 |
| S5 | 结果核验与回传、完成后修订 | 检查文件范围、存在、非空及内容；保存后回传主 Agent；修订沿用事项并产生新的执行及成果 | S4 |
| S6 | 异常与退出收口 | 工具错误、引擎断开、超时、停止、重启对账不假报成功、不盲目重放；权限外动作被拒绝 | S4、S5 |
| S7 | 端到端与交付核对 | 完成下表验收，检查变更与运行说明，记录真实消耗和限制；用户可复现 | S6 |

S1 若发现不能按公开接口完成主 Agent 工具派发或独立会话控制，应先记录具体阻碍并修订方案；不能默默改成单线程伪分工，也不直接更换已定引擎。

不将所有步骤预先估算成固定工期。S1 通过后，再依据接口与环境事实评估剩余工作。

## 4. M0 验收场景

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 连续问答 | 正确保持主对话上下文，简单问题无需派发 Worker |
| T02 | 交代整理测试会议笔记 | 有持久事项和独立执行记录，真实 Worker 创建非空 Markdown |
| T03 | 执行中询问进度 | 主 Agent 能响应，状态来自记录与执行事实，不编造进度 |
| T04 | 文件完成后查看成果 | 路径在许可范围、文件可读、内容与样例一致，不杜撰负责人和日期，回复含摘要与路径 |
| T05 | 要求按负责人分组修订 | 沿用原事项、新建执行尝试，生成新版本；原成果保留 |
| T06 | 模糊指代与第二件执行请求 | 不确定时询问；多个独立执行可并行，主 Agent 可查询；停止只影响指定执行 |
| T07 | 文件不存在或执行失败 | 原因可见，记录失败，不输出虚构成果；重试需显式触发 |
| T08 | 取消、超时 | 请求与停止确认分开；只在确认终止后标 cancelled，无法确认时如实记录 |
| T09 | 运行中关闭并重启程序 | 已完成记录和成果可查询；未完成任务对账后中断或恢复，不自动重复外部动作 |
| T10 | 重复执行事件／重复请求 | 同一执行不重复派发、不重复完成；结果投递有持久状态，无法确认时不虚报已送达 |
| T11 | 读取范围外资料或要求新增权限 | 程序与执行环境维持实际能力边界；主 Agent 按真实授权判断，不通过提示词扩大宿主能力 |
| T12 | Worker 提问／授权与升级用户 | 主自主批准／拒绝／回答；必要时升级用户，主可继续聊天；原 Worker 继续；多项不串线、重复／过期／停止／重启均明确处理 |

## 5. 验证方法

- 对事项状态、重复派发、任务队列及回传处理采用先失败后通过的行为测试，先确定契约再实现。
- 用模拟引擎覆盖超时、断连、停止未确认与重复事件，避免通过真实高风险操作制造故障。
- 用实际 Codex、实际测试文件跑 T01–T05 的核心闭环。安全的真实停止和重启检查也应执行，其余故障明确区分模拟与实际。
- 只报告观察结果。缺少授权、网络或可用模型时明确阻碍；模拟测试通过不能标成端到端通过。
- 验收证据放 .codex/scratch/ 对应子目录，不含凭据或私密用户材料。持久维护一份非敏感的运行说明与验证摘要，入口由项目 README 链接；实际实现时创建，不提前填造结果。
- 开发中主动把获准、脱敏的实际使用反馈补成稳定 ID 的回归用例，沿用原问题 ID；区分真实用户反馈、需求推导和合成样例，不默认保存原始对话或用户文件，不自动上传。维护入口为 [回归用例索引](../tests/scenarios/README.md)。
- 每例记录初始条件、顺序消息／操作、输入 fixture、可观察预期及禁止行为、清理与重跑。行为修复适用先失败后通过；普通测试不得隐式调用生产资源，真实模型通过必须有实际检查和环境／用量记录。

## 6. 性能记录

M0 记录空闲、单 Worker、主 Agent 查询期间整个进程树的内存与 CPU、完成耗时及可获得的模型用量；记录引擎和模型版本。不在 M0 做三 Worker 并行对比，也不先做未经测量的优化。

## 7. 交付内容

- 可运行的 CLI 与 Codex 接入代码，以及必要的依赖和示例配置（不含凭据）。
- 持久事项／执行记录，独立执行、真实文件成果和结果回传。
- 通过的行为测试、真实闭环记录、启动／停止／重启说明和已知限制。
- 对应需求与技术文档更新，不能让实现与 M0 范围脱节。
- 维护中的非敏感回归用例及独立离线／模型入口；当前 HMR-MEETING-001 为需求推导流程配合成会议输入，不能记作真实用户反馈。

## 8. M0 之后的增加顺序（建议）

1. 多 Worker 和原进程授权／提问往返已纳入；三种运行中追加方式为独立后续任务，跨进程精确恢复另行设计。
2. 选一个有需求的浏览器或 Office 工具，跑通真实工作，不同时铺开全部生态。
3. 选一个 IM，将输入、进度、文件与确认接入现有客户端；需要时再拆分服务生命周期。
4. 按试用反馈增加自主安装、语音、定时自动化、模型策略与账号付费。

原先完整 P0/P1/P2 的需求清单仍保留在需求文档中作为演进目标，不作为 M0 必须一次完成的清单。


T12 的需求推导回归见 [HMR-INTERACTION-001](../tests/scenarios/worker-interactions.md)。业务问答／升级用户／原进程继续及旧主线程加载新工具已用真实 CLI 验证；授权批准／拒绝、原生协议请求与生命周期有本地 fixture 回归。真实原生审批在保留 environments=[] 的当前环境未触发，不能将 fixture 或 ask_main 记作原生审批实测通过。具体版本、证据与限制见验证记录最后一节。
