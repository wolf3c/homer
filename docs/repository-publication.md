# 仓库公开与同步

## 公开边界

Git 跟踪的文件默认公开。产品需求、设计、技术方案、架构、源码、提示词、Skill、测试、示例、构建配置及可公开的验证结论均在同一仓库维护。发布直接使用已提交源码，不按目录导出第二套文件树。

凭据、个人及客户数据、内部运营材料和含敏感内容的原始运行记录保存在 Git 忽略的 `.codex/private/`。临时调查和检查输出位于 Git 忽略的 `.codex/scratch/`。需要对外保留的技术结论先脱敏，再写入正常文档目录。

`.gitignore` 不会移除已经跟踪的文件，也不会清除历史。新增公开文件时应检查内容和引用，提交及推送仍以当前任务授权为准。
