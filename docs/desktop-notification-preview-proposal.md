# Homer 桌面通知正文预览方案

2026-11-23 · 已接入源码并通过定向离线验证。安装包系统通知待验。触发、去重和点击规则见[桌面消息提醒](architecture/desktop-message-notifications.md)。

ChatGPT dot 的参考截图在标题下直接显示消息内容，并在末尾截断。Homer 保留标题「Homer」，在同一位置显示最终答复的首段或待办动作。参考截图仅用于确定信息呈现方式。

## 通知文案

| 事件 | 取值和示例 |
| --- | --- |
| 成功回复 | 取已正式提交的最终答复首个可读段落，如「已核对三份报价，第二份包含运费，预计周五送达。」 |
| 仅附件 | 已提交消息有附件引用且无可读正文时显示「收到附件」。有可读正文时优先显示正文。 |
| 失败或中断 | 复用宿主面向用户的明确状态，如「当前额度不足，请查看账号与额度」。缺少明确状态时用「本次回复未完成」或「本次回复已中断」。 |
| 待答、审批、配对 | 分别显示「有问题等待回复」「有操作待你确认」「请确认新设备配对」。 |
| 已有通知事件但无可用预览 | 沿用当前通用文案。空轮次、流式片段和回滚事务沿原触发规则处理。 |

成功回复优先使用宿主已有的 `final_answer`。仅当来源已明确是正式答复时才直接取提交行的正文。复审用合成消息复现了两种情况：成功回复的历史正文可能以过程播报开头，失败回复的历史正文可能以中断前的片段开头。失败和中断的预览只取状态文案。 [原生终态](../src/engine.ts#L1043) · [主回复提交](../src/service.ts#L1454) · [最终答复提取](../src/service.ts#L1869)

Worker、定时和渠道触发的结果，沿现有来源、事项和授权检查，在 Homer 正式向用户提交后才可预览。Worker 内部回报、仅发给主 Agent 的 `ask_main`、自动审批和过程播报留在原入口。对话待办沿可处理状态和原 `interactionId`，配对沿已有候选 ID。两项通知开关命中同一待办时仍只提醒一次。 [后台交付授权](../src/service.ts#L1546) · [待办状态](../src/worker-interactions.ts#L162)

## 实施接点

1. **宿主取值。** 沿现有正式提交接点准备预览，提交成功并通过当前线程、用户可见性及撤销检查后，随 `desktop_notification` 传一个可选短正文。复用现有 Markdown 解析，取首个可读段落中的文字，跳过链接、图片、代码和 HTML 节点，收拢空白。用 `Intl.Segmenter` 按字素截取，候选上限为 120 个字素及 1 KiB UTF-8，截取时加「…」。缺失或提取失败时保留通用文案和原点击目标。 [通知候选](../src/service.ts#L2142) · [Markdown 解析](../src/message-links.ts#L1)
2. **Electron 展示。** 继续用原生 `Notification`，把短正文填入 `body`。前台卡片检查和点击仍只传 `kind`、`id`、`threadId`，定位到原消息、对应过程行、待答卡片或配对设置。窗口焦点、两项开关、运行期去重及点击后的有效性检查复用现行路径。 [原生通知](../packaging/electron/main.mjs#L835) · [点击定位](../ui/homer-app.tsx#L1335)

超过 16 KiB 的原始 Markdown 跳过预览解析，沿用已有兜底文案和定位。这样避免大回复阻塞宿主，也避免把截断的 Markdown 当成普通文字展示。

预览是对已有内容的确定性摘录，无需模型调用、额外存储、新依赖或通知队列。

## 隐私与系统行为

旧版只向操作系统提交通用文案。按已确认的方案，现有通知开关触发时会向系统提交获准答复的短片段，待办仅用固定动作文案。正文可能含姓名、凭据或路径，Markdown 处理无法保证脱敏。操作系统可能保留已经收到的预览，撤销原消息或关闭 Homer 通知开关不会追溯删除。

实际可见行数、截断、系统分组、锁屏显示、专注及勿扰由操作系统决定。macOS 提供「解锁时」和「永不」等预览选项，Windows 提供锁屏内容控制。Homer 在已有系统通知设置入口旁说明预览行为。 [macOS 通知设置](https://support.apple.com/en-bh/guide/mac-help/-mh40583/mac) · [macOS 专注模式](https://support.apple.com/en-euro/guide/mac-help/mchl613dc43f/mac) · [Windows 通知设置](https://support.microsoft.com/en-us/windows/experience/notifications-and-do-not-disturb-in-windows)

## 验证

- **复审基线** 已静态核对 Homer 0.1.23 build 311 的宿主及 Electron 通知路径。17 项定向离线用例通过，并以合成消息复现过程播报、失败片段和过程行定位。受沙箱限制，宿主用例在隔离环境中替代了进程身份查询。
- **实现验证** 隔离宿主、Electron 壳用例及真实设置组件的合成渲染覆盖最终答复、失败、中断、附件、空白、Markdown、字素截断、回滚、授权失效、前台规则、去重和按原 ID 定位。Electron 壳测试替代系统通知，同时核对正文没有进入网页的可见性检查和点击事件。
- **安装包待验** 用合成消息在 macOS 签名包和 Windows NSIS 包上验证系统授权、锁屏预览、专注或勿扰、正文截断和进程运行时的通知中心点击。 [Electron 平台要求](https://www.electronjs.org/docs/latest/tutorial/notifications#platform-considerations)
