# 桌面截屏批注方案

2026-11-09（Asia/Shanghai）。macOS 27.2 的 Apple Silicon 隔离签名候选在屏幕录制与辅助功能均未授权时，从系统选定的合成窗口取得 1360 × 844 PNG。实测走通圈选、加入草稿、刷新重开、发送和历史查看，合成引擎收到一份图片和对应批注。首版已移除 OCR。AX 探针另在用户手动授权后交叉选取同一 App 的两个窗口，两次均只命中所选窗口的内容标记，录屏权限保持关闭。

2026-11-10（Asia/Shanghai）。可选 AX 摘录已接入截图草稿和发送。在 macOS 27.2 签名隔离候选中实测两次选取 E101。录屏权限始终关闭。无辅助功能授权时取得图片，有授权时也取得所选窗的 AX 摘录。刷新后可重开同一附件，合成引擎收到一份图片、对应批注和摘录。E202、安全文本框及画面外的合成标记均未出现。多图编号由合成输入回归覆盖。

同日补测 Chrome 与 TextEdit。全局录屏关闭时，TextEdit N101、N202 均取得所选窗口的截图。N202 的 AX 摘录只命中本窗，N101 验证了无 AX 时仍可批注和发送。修复了高图弹窗遮住操作按钮、完成时读取旧附件列表的问题。修订构建的高图用例通过圈选、加入、刷新重开和发送，主输入框回归 50 项通过。

Chrome AX 修正已接入现有 Swift 采集 helper，并在重新构建的签名隔离候选中通过验证。全局录屏始终关闭。授权辅助功能后，C101、C202 的截图和 AX 摘录分别只命中所选窗口。未授权时的 C101 和授权后的 C202 均走通圈选、加入草稿、刷新重开、发送和历史查看。合成引擎每次收到一张图和一条批注，只有 C202 随附本窗 AX。

同日迭代选窗体验。在已有录屏授权的测试进程中，合成双窗通过悬停遮罩、重叠窗口优先级、单击取窗和 Esc 取消。100 × 60 点的反向拖选实际得到 200 × 120 像素 PNG，仅含目标颜色，无取景遮罩或 AX。相关离线回归 161 项通过，Apple Silicon 本地签名候选通过独立档案启动验证。多显示器交互和用户手动授权后的完整体验待试用验收。

同日修订批注弹窗布局。弹窗最多宽 1280 CSS 像素，保留窗口边距。长图和窗口文字在中间区域滚动，标题、批注入口和底部操作保持可见。合成横图、长图及窄窗对照验证通过，滚动后新增批注的原图坐标和草稿提交一致。

提交前复核移除了三处重复工作。选区未变化时不重绘遮罩，变化时只重绘各显示器受影响的区域。明确拒绝已处理后，状态推送不再重复查询原回执。模型传图复用一次原文件校验。合成回归也覆盖了响应丢失后主动核对、显式重试保留原请求，以及桌面启动夹具的数据库版本与锁恢复。

同日接入原位浮层。当前签名隔离包用合成截图和离线引擎验证了蒙版、长图滚动、Esc 取消，以及 Enter 保存备注后再发送。图标发送与 Enter 发送各提交一张图并显示历史答复，窗口文字可按需附带。全屏焦点与双屏另行验收。

同日优化取景到批注的交接。签名隔离包用 2000 × 1250 的两份合成 PNG 做前后对照，每份各测四次，模拟约 220 毫秒取图。约 0.5 MiB 和 5.4 MiB 的图片从选定到浮层可批注的中位耗时分别从约 690、700 毫秒降到约 290、320 毫秒。离线回归 462 项通过，隔离包复测圈选、取消、图标与回车发送及历史查看。

## 1. 范围

用户在别的应用看到报错时，可以按快捷键截下窗口或一小块画面，在原位浮层圈出报错、写一句要求，直接发送给 Homer。发送会连同当前草稿一起提交。支持图片输入的模型直接接收截图。

macOS 复用荷马在「本机权限」中管理的屏幕采集授权。授权后，快捷键直接截取前台窗口。无法确认焦点窗口时，进入荷马取景层。手动选窗或拖选可从「显示 → 选取窗口或区域…」进入。拖选区域提供图像，窗口截图可按原规则附带 AX。Windows 的入口和取帧见下文。

## 2. macOS 使用流程

1. Homer 运行且普通主草稿可用时，从其他应用按截图快捷键截取当前窗口，默认是 `⌃1`。若尚未授权，快捷键会打开「设置 → 本机权限」。在「屏幕采集」下点击「打开系统设置」，允许当前荷马应用录屏，再回来重新检查。系统要求重开时，重开后再按快捷键。「设置 → 截图批注」提供功能介绍和与首开导览共用的动图示意，点击键帽可修改全局快捷键，旁边的恢复图标可恢复默认组合。手动取景时，可单击高亮的窗口或拖出矩形，按 Esc 取消。手动入口在未授权时仍可通过 macOS 的单窗口选择器取得本次授权。[Apple 录屏权限说明](https://support.apple.com/zh-cn/guide/mac-help/mchld6aa7d23/27/mac/27)
2. 截下目标后，半透明黑色遮罩压暗所在屏幕，可直接在截图上拖框批注。取消和发送固定在截图可见区域的右下角，滚动长图时也能点击。备注内按 Enter 保存、Shift+Enter 换行。有 AX 摘录时，可在「窗口文字」中查看或取消附带。
3. 点发送图标，或在没有输入、绘制及待保存批注时按 Enter。截图随当前草稿提交，忙时按原规则排队。准备期间草稿有新编辑时，截图留在草稿里供核对。准备失败保留编辑内容和原上传身份。发送前按 Esc 或点取消图标，丢弃本次临时内容。[Homer 界面约定](../ui/DESIGN.md)

## 3. macOS 采集与 AX 验证

Electron 主进程用 `globalShortcut` 注册快捷键，并将自定义组合保存在已有桌面档案。macOS 支持 Control 加数字，也支持含 Control 或 Command 的至少两枚修饰键，加字母或数字。先尝试注册新键，保存成功后再释放旧键。注册冲突或写入失败时保留旧键。设置打开时暂停截图触发，关闭后即用当前组合。[Electron 全局快捷键](https://www.electronjs.org/docs/latest/api/global-shortcut)

Swift helper 检查屏幕录制授权。快捷键缺少授权时，主进程打开现有权限页。授权后按前台进程选取唯一可见窗口，已有辅助功能授权时可以用焦点窗口区分同一应用的多个窗口。窗口仍按 ID、进程和几何确认后采集。手动取景用原有 AppKit 取景层，单击窗口或松开拖选后读取画面，未授权时走 `SCContentSharingPicker` 的单窗口授权。区域限制在起始显示器，通过 `SCStreamConfiguration.sourceRect` 取帧。所有路径共用 `SCStream`，收到第一张完整画面后停流，取帧有 10 秒截止。[Apple 系统选窗授权](https://developer.apple.com/videos/play/wwdc2023/10053/?time=1521) · [Apple 截取矩形](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/sourcerect)

Swift helper 在停流后编码 PNG。沿用 8 MiB 和 4000 万像素上限，超限请用户选较小的窗口或区域。批注使用这张图的原始像素坐标。[现有上传限制](../src/web-upload.ts) · [图片像素限制](../src/media-policy.ts)

沿现有桌面包的构建、签名和资源校验路径。开始采集时，主进程在后台准备浮层和批注器。校验后的图片加载完成才显示浮层。浮层加载超时、失败或在发送交接前退出时，交回原会话的批注入口。浮层通过专用桥接提交批注和附带窗口文字的选择，由发起采集的主帧确认接收。导航、取消或草稿身份变化会使交接失效。发送前，图片和批注只保存在本机临时编辑中。[桌面主进程](../packaging/electron/main.mjs) · [桌面包签名与清单](../packaging/electron/forge.config.mjs)

窗口截图用 `AXIsProcessTrusted()` 检查已有授权。未授权时直接交回图片。已授权时以所选窗口的 ID、进程和几何信息核对身份，再用目标进程的窗口位置、尺寸和标题确认唯一 AX 窗口。窗口列表与几何用于身份匹配，内容读取限定在匹配窗口的子树。身份无法确认、匹配变化或超过取帧后 600 毫秒时，继续交回图片。[Apple 窗口标识](https://developer.apple.com/documentation/screencapturekit/scwindow) · [Apple AX 授权检查](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted)

Chrome 的网页 AX 树可能在读取应用角色后才出现。窗口标题接受原始标题或带当前应用名后缀的标题。读取时区分可见子节点属性不可用与明确返回空列表，只有前者才继续查询普通子节点。

摘录保留可见控件的角色、名称与值。优先遍历应用报告的可见子节点，并核对子节点所属窗口和可见边界。编辑框只取应用提供的可见文字范围，跳过安全文本框。每张图最多 24 个节点和 4096 个 UTF-16 代码单元。模型看到的是应用提供的原文和现有批注坐标。权限由 macOS 按 App 管理，单窗口范围由采集器的身份与子树校验实现。其他 App 的字段覆盖取决于它们暴露的 AX 信息。[Apple AX 属性](https://developer.apple.com/documentation/applicationservices/carbon_accessibility/attributes)

## 4. 批注与草稿

- **一个批注器。** 截图浮层与主草稿复用 Annotorious、备注表单和几何校验。成果预览继续逐条保存。带附加内容的图片可从附件入口重开同一个编辑器，刷新后按原草稿身份取图。[图片批注器](../ui/image-annotation.tsx) · [桌面网关](../scripts/dev.mjs) · [宿主媒体路由](../src/dev-host.ts) · [草稿图片读取](../src/service.ts)
- **一张图，一个附件身份。** 沿用 `/api/uploads` 和原图准备流程。只有图时走普通图片附件。有批注或 AX 时，同一条「本轮附件图片」引用绑定 `assetId/revision`、像素尺寸、批注和可选 AX。服务复用上传归属与解码尺寸校验。删最后一条批注时仍保留已选择附带的 AX。移除图片时一起清除引用。[附件适配器](../ui/homer-attachment-adapter.ts) · [引用合同](../src/preview-reference.ts) · [媒体校验](../src/media-store.ts)
- **一次加入。** 用现有 `threadId/requestId`、草稿代数及 `uploadId` 核对归属。重试用同一个上传身份，图片和引用都确认后才允许发送。准备中取消或切换草稿时，先作废这次加入，等原上传明确结束再撤销暂存附件。回执未知时保留原上传身份待核对，不能把尚未查到附件当作撤销成功。专用待答沿现有附件限制。[主输入和附件准备](../ui/homer-app.tsx) · [附件撤销](../src/service.ts)
- **一条发送路径。** 正文和用户备注表达任务，AX 摘录作为应用界面的来源材料。截图作为一份原生图片输入交给模型。有多张图片时按实际模型输入顺序标注截图编号。历史引用显示已附带的窗口文字。队列沿用现有规则和存储。[用户意图规则](../src/user-intent.ts) · [发送顺序](../src/service.ts) · [队列规则](../src/recursive-main-inputs.ts)
- **回执和兼容。** 桌面网关的「已暂存」仍需核对最终回执。服务立即拒绝图片来源，或通过现有 `/api/history/receipts` 返回同一请求的迟到拒绝时，走同一草稿恢复逻辑。当前输入仍是该次发送留下的空草稿才自动恢复。已有新编辑时保留原请求供核对。未知回执只用原请求和原内容核对或重试。沿已有对话合同版本检查启用新引用，覆盖发送、队列、历史和恢复。旧组合无法完整处理时提示更新，保留原草稿和待确认请求。[桌面回执](../scripts/dev.mjs) · [草稿恢复](../ui/conversation-client.ts) · [对话合同](../src/web-contract.ts)

## 5. 实施顺序与验收

1. **先验采集。** 录屏授权关闭时，快捷键应打开本机权限页，手动入口仍可系统选窗。已有授权时，快捷键应截取能确认的前台窗口，焦点无法确认时再进入取景层。核对手动选窗、反向拖选和 Esc 取消。区域图片仅包含所选矩形，无取景遮罩和 AX。所有路径都在取得第一帧后关闭分享流。
2. **再接草稿。** 用合成 PNG 覆盖圈选和输入法、只发图、删最后一注和删图。让上传延迟，确认重复点击只加一次，取消或切换后晚到的图片能撤销。模拟先暂存后拒绝、未知回执和旧协议组合，确认原请求能核对或恢复，后写的草稿得到保留。
3. **最后走完整流程。** 在同一隔离桌面构建上完成「截取 → 批注 → 加入」。刷新后从原附件重开编辑器，再发送并从历史查看。核对有辅助功能授权时 AX 标记只来自所选窗口，无 AX 时图片和批注仍能发送。合成引擎核对一份图、用户批注和可选摘录，历史显示原始回复。线上模型的图片收发兼容性按发布范围单独验证。[Homer 测试边界](testing.md)

## 6. Windows 11 x64

全局快捷键默认 `Ctrl+Shift+F2`。在「设置 → 截图批注」可改为 `Ctrl+Shift` 加字母、数字或 F1–F11，也可恢复默认。快捷键与「显示 → 选取窗口或区域…」打开同一个浮层。可从列表选一扇窗口，或点击「框选区域」后在鼠标触发时所在的屏幕拖选。窗口图在该屏幕上批注，区域图贴着原选区显示。截图和批注沿现有草稿及发送流程提交。

Electron 45 枚举窗口 ID 和标题，省略缩略图。主进程核对所选来源，只在当前草稿所属浮层的可信主帧有用户操作时授权一次视频流。区域模式先隐藏选择器，再取对应显示器的一帧，停流后显示冻结画面。按实际帧尺寸换算裁切，未选中的屏幕和整屏冻结画面不进入草稿。窗口和区域都复用原 PNG 上限、批注器、发送回执和 NSIS 资源清单。Windows 首版仅收集图片和批注。

`windows-2022` x64 runner 用 Electron 45.0.0 验证两扇合成窗口分别命中所选像素，首帧分别为 363 和 182 毫秒。隐藏选择器后区域首帧为 58 毫秒，恢复显示的对照捕获到洋红标记。该结果覆盖原生取图探针。产品代码另在本机 Electron 用合成媒体和回环会话走通两条路径，各发送一张图和一条批注，历史读回的 PNG 摘要一致。Windows 11 的 NSIS 候选和原生端到端仍需单独验收。[原生像素记录](https://github.com/wolf3c/homer/actions/runs/42825837381/job/129862871687) · [Windows 候选验收](testing.md#windows-截图批注)
