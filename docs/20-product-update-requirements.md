# 正式产品的自动更新要求

确认日期：2026-10-17。状态：用户已确认，必须在后续完成；尚未完整实现。本文是长期产品要求，不表示已具备发布更新服务，也不扩大当前日常环境维护操作的授权。

## 已确认方向

Homer 正式产品必须具备“版本兼容清单＋固定迁移程序＋本机副本预演＋启动验证”。发布者在发布前审核兼容性与迁移，用户电脑按明确规则自动检查和执行，不依靠本地 Agent 临时改代码、推测数据库兼容性或要求用户审阅源码。

更新采用后台下载与准备、安全空闲后切换、恢复原对话、失败可恢复的路径。正在生成的回复、Worker、待答交互、活跃发送及未知执行归属继续受保护。用户已明确该路径足够，跨版本并行 Worker 和忙碌时推广后台不作为本要求的完成门槛。

## 必须完成的能力与验收条件

| 编号 | 能力 | 完成条件 |
| --- | --- | --- |
| HMR-UPDATE-PRODUCT-001 | 版本兼容清单 | 每份发布声明可升级的来源版本、目标版本、数据库与工具/消息协议版本、运行环境及所需权限；不支持、未知或缺少迁移路径时明确拒绝，继续可用旧版。 |
| HMR-UPDATE-PRODUCT-002 | 更新包真实性与完整性 | 更新器验证发布签名和文件校验值；篡改、截断、来源不可信或不匹配的更新不能进入执行阶段。签名密钥不随客户端分发。 |
| HMR-UPDATE-PRODUCT-003 | 固定版本迁移 | 按明确来源与目标顺序执行经过验证的迁移；每一步有事务或明确的恢复边界、版本记录及重复执行保护；未知未来版本、部分失败和重启不得猜测完成或重复破坏数据。 |
| HMR-UPDATE-PRODUCT-004 | 本机一致性备份与副本预演 | 核对空间和权限，建立包含已提交 WAL 的一致性备份，在保护目录副本上运行同一迁移；检查完整性、外键及原主对话、历史、来源、请求幂等身份和未知发送事实保持。预演失败不修改正式库。 |
| HMR-UPDATE-PRODUCT-005 | 安全切换与原身份恢复 | 等待明确安全空闲，确认旧 owner 与引擎正常关闭、锁释放后切换；原账号引用、原主 thread 和队列身份保持。不创建替代主对话，不盲重放未知执行或发送。 |
| HMR-UPDATE-PRODUCT-006 | 启动与采用边界验证 | 区分进程已启动、服务 ready、原对话恢复、输入持久接收和模型已采用；检查版本/API、数据 owner、原主身份及渠道恢复。失败必须可诊断，不以端口可达代替完整验证。 |
| HMR-UPDATE-PRODUCT-007 | 回退与前向恢复 | 新版尚未产生新业务事实前，可恢复同维护点备份及匹配旧程序；已经接收新输入、执行或发送后禁止盲目覆盖旧快照，保留事实并走明确的前向修复或恢复流程。 |
| HMR-UPDATE-PRODUCT-008 | 更新器和运行依赖 | 提供经过验证的启动器自身替换及依赖兼容路径；需要更换负责更新的进程时有独立引导或等效恢复方案，不能假定更新器可原地替换自身所有状态。 |
| HMR-UPDATE-PRODUCT-009 | 自动处理与人工介入 | 普通已验证升级可在既有用户更新设置和权限下自动完成；新增权限、登录、无支持路径或不可自动恢复时明确说明所需动作。诊断不含正文、凭据或原始响应。 |

## 贯穿验收

必须覆盖支持的旧版本升级、重复执行、下载篡改、空间不足、备份/迁移/启动各阶段失败与进程中断、未来 schema 拒绝，以及新版接收后禁止盲回退。验证原对话与历史保持、Worker 未被更新强杀、微信等渠道只有一个 owner、未知发件不重发。测试先用隔离合成环境，再按授权完成真实安装环境的升级与恢复；每项保留环境、版本、实际退出码和结果，不用合成通过代替真实上线证据。
