## 实现

- 顶部头像后显示当前 Worker 工作中、执行完成、有效待用户交互数量；状态入口收起时也共享只读快照。首次读取不报零，旧快照清楚标记，不以动画表示实时运行。
- 每事项一张卡；多个 Worker 在事项内，单个合并。TaskCard 使用官方默认折叠，Plan、最新公开 output、子 Worker、后续待办位于所属展开区。父折叠卸载后，子卡片重开默认收起。
- 计数包含子 Worker，以任务身份去重，不按同名或 executorAgentId 合并；只取当前版本/Run。执行、验收、交付分开。成功待验收可以是执行完成，失败/取消/未知不算完成。
- 返工标记只来自同任务前序 Run 的 revision_requested 事实，不从版本号推断。停止待确认、状态未知和暂停使用通用 Card。
- 状态变化通知合并为至多约每两秒一次快照刷新，打开/恢复可立即核对；不为每个 Worker 创建轮询。面板外观关闭不停止入口计数更新。隐藏页面中止读取，恢复后核对。
- 公开进展以 task/version/run/epoch/thread/turn 精确绑定。未完成文本增量在进入身份读取前直接跳过，避免逐增量查询数据库。仅采纳原生结构化计划、已完成公开 commentary/final_answer 文本、固定工具类别名。内部推理、工具参数和原始结果不进入该投影。原 run.summary 仅作明确标注的旧说明。
- 线性计划必须具有已完成前缀、单一当前步骤、后续 pending，或全部完成；其他结构用 TodoList 逐项表达，不假装线性完成。
- 后续待办渲染器只接显式 next 记录。现有原生事件尚没有独立 next 来源，生产数据缺少时隐藏；不从摘要推导。浏览器夹具中的 next 为明确合成内容。
- 新 GET /api/tasks/:root/progress 复用原 loopback Host/Origin 约束，无数据库迁移。开发 IPC 的 taskOverview.progress 同步归为只读。
- 原任务阅读器保留，日常顶部旧入口移除。Run Activity 仍能读准确历史版本；待答沿原交互核对后关闭浮层、滚动并聚焦到原卡；Canvas、发送草稿、停止和队列保持。

## 代码审阅与提交验证

用户授权 review 与 git commit 后，进一步修正空计划无法清除、断线中止请求留下 loading 缓存、首次打开排序缓存过早建立，以及窄屏大计数溢出；执行展示身份补齐 threadId，线程重绑定也会重置卡片与进展。总览、进展与待答定位的读取均有 15 秒超时，超时保留旧记录并可重试；正常关闭、切换和断线的中止不误报读取失败。

快照变化才建立树、统计、事项优先级、执行签名及子级索引；同次阅读的顺序用 Map 固定，展开进展按 taskId 索引，不为每个 Worker 线性扫描同根进展。子级折叠沿已建邻接表处理。根事项进展用两条 SELECT，只投影当前 Worker 精确身份，不再读取全局成果、交付、交互和协调信息。仍使用现有表与索引，不增加数据库迁移。

大量事项首次显示 20 项，可在原浮层继续显示，每次增加 20 项；数量始终统计完整快照，重开回到首批。合成千事项场景在同机 Chrome 中 DOM 节点由约 14,700 降到 900；点击至后续绘制的单次观察从约 294 ms 降到 101 ms，包含自动化调度，不能作为生产延迟保证。继续显示至 40 项及焦点保持已验证。320px 的 3,000 工作中 / 1,000 完成 / 1,000 待处理入口完整位于视口内。

纯 CPU 合成量测（Node v26.9.0，同机九次中位数）：1,000 个事项、4,000 条任务的旧排序约 76.5 ms，索引后约 1.4 ms；3,000 个事项、12,000 条任务约 250.6 ms 对 3.6 ms。这仅量测排序与树投影，不含 SQL、网络、DOM 或真机成本，不宣称无限数据规模或生产性能保证。
