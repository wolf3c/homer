## 消息 Markdown 本地文件链接 Preview（2026-11-18）

用户点击消息里的本地文件链接，Homer 直接尝试读取路径当前的文件并在现有 Preview 打开。历史消息沿用同一入口，文件仍可读取就能打开，使用原路径恢复文件后也能重试。每次点击或重试按当时的内容读取，已打开的内容无需自动跟踪磁盘变化。正式附件仍是固定版本的交付方式，用户需要保留当时内容时可以另行使用。路径链接和附件各自可打开，同名、同路径或文件内容变化均不把两者互相替换。网页链接沿用当前行为。

### 源码定位

- 消息 `Markdown` 为链接安装点击处理，传入渲染后的 `href`。桌面 `openBrowserLink` 却按 DOM 的 `trigger.href` 检查 HTTP(S) 并打开网页，`/tmp/report.md` 此时已解析为 Homer 页面同源的 HTTP URL。渲染层也有另一道差异。当前 Markdown 依赖的默认 URL 转换会清空 `file:` 和 `C:/…` 形式的目的地。其余点击按普通锚点处理，Electron 外部链接也只放行指定协议。当前链路没有按消息路径读取文件的分支。 [消息渲染与点击入口](../ui/homer-app.tsx) · [桌面导航](../packaging/electron/main.mjs)
- 文件 Preview 的入口来自附件。前端按 `messageId + assetId + revision` 请求 `/api/media/…`，并校验附件摘要；服务端核对消息可读性和附件授权。独立的本地文件读取能力已在 `readLocalAttachment` 中使用，包括为 Markdown 附件解析相邻图片。相邻图片路径借助附件原路径解析，附件正文仍来自快照。这条资源分支无法直接接收消息里的任意文件路径。 [Preview 读取](../ui/canvas-panel.tsx) · [HTTP 媒体入口](../src/web-server.ts) · [宿主读取](../src/service.ts)

### 最小改法

1. 在消息 Markdown 解析链保留链接目的地，拿到浏览器补齐 origin 和默认 URL 转换前的值。可以先试在现有 Markdown 渲染器的链接节点里传递该值，仅让识别为本地候选的链接进入受控点击处理。保留默认 URL 过滤，不把 `file:`、盘符或其他被过滤的协议放到可导航的 DOM `href`。HTTP(S)、`//host/…`、锚点及其他普通链接继续走原入口，网页快捷点击与外部打开规则也沿用。无需扫描渲染后的 HTML 或依靠链接标题推断。
2. 单个前导 `/` 的路径有歧义。建议先验证能否让明确的 Homer 站内路由沿用网页入口，并在点击时将其余单斜杠路径作为绝对文件候选，由宿主按现有读取边界尝试，读到文件就预览。核对实际消息里的网页根相对用法，据此确定路由与文件同名时的优先级，以及未命中时何时沿用网页行为、何时显示文件缺失。后缀规则会漏掉无扩展名的文件，存在性规则会把已移动或删除的文件留在歧义状态。明确的本地链接可用 `file:///…` 表达。历史链接需覆盖中文、空格、百分号与末尾 `:行号`。按平台解析合法编码，若兼容行号后缀，优先尝试完整文件名，避免把文件名中的冒号误作行号。Windows 盘符、反斜杠及远程 `file://host/…` 或 UNC 形式的识别和授权应按平台验证。相对文件路径只在能确定该消息原工作目录时尝试，缺少可靠基准时保留现有链接行为，避免用当前 Worker 目录解释旧消息。
3. 由可信的 Homer 界面在用户点击后发起一次只读请求。宿主按消息身份校验当前会话及可见性，并从该消息的链接目的地解析要读的目标。复用本地读取的真实路径、受保护管理目录、普通文件、链接、大小及读取期间一致性检查。`readLocalAttachment` 的现有路径校验主要排除 Homer 管理目录，读取授权仍由调用入口负责。受信桌面入口应覆盖权限内的既存历史绝对路径，避免把当前项目目录、活跃 Worker、附件或批准记录另设为普遍前置条件。无须在消息渲染时探测路径，也无须新增文件工具、注册表、附件版本或历史迁移。移动或其他远程入口涉及读取宿主文件时，须单独验证通道和调用方权限，再接入这条能力。
4. 复用现有 Preview 标签、读取提示和渲染组件。将当前文件读取结果接到文件渲染层，保留附件分支的版本核验，路径来源不伪装成附件。现有 Preview 可展示 Markdown、文本、图片、PDF、补丁、浏览器可播放媒体及受隔离的 HTML，实际可用格式还取决于本地读取的 MIME 判别和渲染分支。优先验证能够直接复用的格式，未知格式沿用明确的不可预览反馈。HTML 若接入，复用现有隔离呈现，页面不得取得宿主凭据或任意相邻文件访问能力。已有基于固定附件来源的批注和引用继续走原链，预览路径当前内容本身无需新增保存或批注实体。

确定为本地文件后，分别提示文件找不到、访问受限、路径指向非普通文件或格式不可预览；读取期间发生变化时可重试，重试仍读同一路径的当前内容。网页内容、后台过程和未鉴权请求均不能凭路径发起本地读取。权限或读取失败时沿同一入口反馈，避免静默打开网页或展示旧快照。

### 验收与状态

- 用无附件的新消息和旧消息点击同一本地绝对路径，验证两者均在相同 Preview 中打开。修改后再点得到新内容，删除后有缺失提示，恢复后重试成功；并列的既有附件仍打开其交付快照。
- 用源码路径、无扩展名、中文空格、百分号、行号以及各平台拟支持的路径形态核对实际点击；以 HTTP(S)、协议相对 URL、网页根相对 URL、站内路由及锚点验证网页行为，覆盖文件与路由重名、文件缺失及无法确定相对路径基准。
- 用隔离桌面实例核对 Markdown／文本与至少一种二进制类型实际呈现，以及缺失、权限拒绝、目录或受限文件、读取变化和不支持格式的反馈。核对跨会话或不可见消息、消息之外的路径、非可信调用和预览内容均不能调用宿主读文件。若接入 HTML 或远程通道，另验隔离和读取权限。

桌面源码已实现。已知 Homer 路由与资源命名空间沿网页入口，其他单斜杠路径按本地绝对路径读取。路由同名文件可用 `file:///…` 指定。路径百分号可写为 `%25`，POSIX 路径优先读取完整文件名，找不到时再解释末尾行号。Windows 路径分支只接受本地盘符，移动端及普通 Web 入口不读取宿主文件。

本地预览复用文件面板、文件检查和 HTML 沙箱。桌面网关校验主窗口身份后，宿主按当前对话的可见消息查找原 Markdown 链接。隐藏过程、跨会话请求、受保护管理路径与文件别名沿相应读取边界处理。附件继续按消息、版本和摘要读取。

隔离 macOS Electron 用真实点击验证了历史裸路径、新回复 `file:///…`、中文空格和百分号、行号和完整冒号文件名、修改后重读、缺失后恢复重试、PNG、无扩展名文本、权限及不支持反馈。并列附件仍读固定快照，HTML 沙箱未触达文件读入口。普通历史消息的 HTTP、协议相对 URL 和 `/connect` 均进入原网页 Preview，Electron 退出码为 0。原生最终回复中的网页链接仍受已有的网页来源身份校验限制。宿主与桌面网关定向回归 36 项通过。安装版、Windows 实机和读取中途变更的时序未验收。
