## 设置和事件范围

桌面「设置 → 通知」顶部显示系统通知权限、勿扰说明及系统设置入口，下方使用与电源设置一致的两个独立开关：**Homer 有新消息**、**需要我关注**。两项默认开启，已有保存的偏好优先。开关只影响之后的系统提醒。应用内继续显示原消息、待处理卡片和「有新内容」提示。

| 事件 | Homer 有新消息 | 需要我关注 |
| --- | --- | --- |
| 正式提交给用户的新回复、主动进度或结果，包括只有附件的消息及已提交的用户可见失败说明 | 是 | 存在明确待办及有效入口时命中 |
| 首次进入用户待处理状态的审批、提问、待补资料或决定，并形成新的用户可见卡片 | 是 | 是 |
| 已有内容后来进入需要用户处理的状态 | 同时形成新卡片或新消息时命中 | 是 |
| Worker 内部回报或 `ask_main`、自动审批过程、流式增量、运行占位、同一记录的重复投影 | 否 | 否 |

「需要我关注」以用户有明确后续动作且宿主能定位该动作入口为准。对话内的人工审批、提问、转给用户的 Worker 待答均沿原 `interactionId`，以仍获授权、未答复的 `pending_user` 为准。只有文字说明的阻塞或问题走普通消息规则。设备配对确认等正式桌面待办可以沿各自的有效状态、稳定 ID 和原设置入口接入。普通版本公告沿现有更新提示显示。当前核实的源码更新审阅入口属于开发运行路径。 [活动交互投影](../../src/web-homer.ts#L252) · [配对审批](mobile-device-pairing-architecture.md) · [开发更新审阅](../../scripts/dev.mjs#L141)

## 开关组合与事件身份

分别应用两个开关和对应的前台规则，任一类别允许即可提醒。同一事件只弹一次。正式回复显示最终答复摘录，待办显示具体动作。无可用正文时按命中的规则回退通用文案。点击打开该事件的原入口。

| 有新消息 | 需要我关注 | 同一张新审批卡的系统提醒 |
| --- | --- | --- |
| 关 | 关 | 无 |
| 开 | 关 | 普通消息规则，后台一条 |
| 关 | 开 | 待处理规则，入口未在前台可操作区域时一条 |
| 开 | 开 | 按并集判定，符合待处理规则时优先；合计最多一条 |

- 普通消息按 `messageId`，对话待办按 `interactionId`，设置类待办按所属模块的稳定 ID。桌面在当前实例内对事件去重。不同待办和独立结果分别判定，即使来自同一事项或用户输入。
- 一个新待办只生成一份候选，两项开关读取同一身份。专门处理 Worker 待答的宿主轮已有 `interactionId`，当前消息提交尚无结构化字段区分专属审批说明和包含独立结果的答复。首版对同一待办事件去重，正式回复按其独立 `messageId` 判定。将来若宿主提交时已有确切关联，可沿同一待办身份。`sourceMessageId` 指向原用户输入，同一次输入可能产生多个待办。 [宿主消息提交](../../src/service.ts) · [卡片来源](../../src/web-homer.ts#L252)

## 焦点与点击定位

**普通消息看窗口。** 主窗口隐藏、最小化或失焦时可弹系统通知。主窗口在前台时沿用「有新内容 · 最新消息」，用户继续阅读旧消息、查看 Preview 或编辑草稿。已有新内容提示是本地视觉提示。 [阅读位置和新内容](../../ui/homer-app.tsx#L1029)

**待处理事项看目标入口。** 后台直接按开关判定。前台由可信主页面在目标卡片出现时按 ID 检查一次，入口已在可操作区域内时抑制。页面未就绪或短时间内仍无检查结果时，按入口不可见处理。宿主发送对话待办前核实其仍可处理，Electron 展示前再读取窗口焦点。通知与业务状态可能短暂交错，点击后核对实时状态。通知到达时保持当前阅读位置、焦点和草稿。 [聊天视口与点击接线](../../ui/homer-app.tsx)

点击时恢复并聚焦当前实例的原窗口，待可信主页面就绪后按 ID 定位。普通消息复用已有历史补页，包括回复在过程行呈现的情况。待答每页最多 80 条。按 `interactionId` 核对原会话和待办有效性，当前页没有目标时读取包含目标的页，复用原卡片并聚焦。设置类待办打开所属设置页。点击仅导航，回复、批准或拒绝仍由用户通过现有控件完成，沿原请求和回执。 [历史按 ID 定位](../../ui/homer-app.tsx#L1140) · [待答分页及点查](../../src/web-homer.ts#L287)

点击时暂时断线，待现有连接恢复后定位一次。已处理、过期、撤销或无权访问时给出状态提示，保留草稿和会话。

## 隐私、系统权限与平台

- 原生通知可显示最终答复的短摘录、失败状态或待办动作。锁屏与通知中心是否显示预览由系统设置决定。通知本身不拼接事项标题、附件名、路径和审批详情。前台检查和点击只传原定位引用。
- 通知设置提供系统设置入口。系统授权与应用开关独立，授权提示、静音、专注模式和勿扰由操作系统决定。Homer 设置页展示用户保存的两个开关。
- **macOS**：当前普通关闭窗口会隐藏，Homer 继续运行时仍适用通知规则。使用签名安装包验证通知授权、横幅、通知中心、隐藏窗口恢复和点击跳转。Electron 45 的权限能力以实际依赖和安装包为准，Codex 包中的自有接线单独看待。 [窗口生命周期](../../packaging/electron/main.mjs#L954) · [Electron 通知 API](https://www.electronjs.org/docs/latest/api/notification)
- **Windows**：当前最小化仍运行，普通关闭沿现有退出流程，退出后停止生成新通知。使用实际 NSIS 安装包核对开始菜单快捷方式、`AppUserModelID`、通知激活身份及最小化恢复。首版点击定位以进程仍在运行为范围，退出后的冷启动定位留待单独验收。 [Windows 打包](../../packaging/electron/forge.config.mjs#L97) · [Electron 平台要求](https://www.electronjs.org/docs/latest/tutorial/notifications#platform-considerations)

## 实现接点与现有边界

1. **宿主生成候选。** 从面向用户的消息正式提交、真实待办首次生效的接点发送类型和稳定引用。桌面聊天就绪前已有定时调度可能产生新事件。先加载两个通知偏好、接好桌面事件通道，再启动会产生候选的调度。现有 `message.committed` 服务渠道消费，异步 Hook 可能合并唤醒，部分本地交付也未满足该 Hook 的渠道发布条件。桌面补齐本地提交接点，沿用原渠道契约。 [启动顺序](../../src/dev-host.ts#L196) · [本地交付](../../src/service.ts#L1533) · [Hook 契约](hook-system-design.md)
2. **Electron 主进程判定、展示和响应点击。** 主进程保存两个偏好，按焦点、目标可见性和运行期去重决定是否调用原生 `Notification`。点击时沿现有可信主页面校验传递本机定位引用。初始化、刷新和重连沿原流程恢复对话及待办。通知仅对实时事件尝试一次，系统抑制或中断时原消息、待办和业务回执仍可查。首版无需通知队列、游标或历史回放。 [桌面调用者校验](../../packaging/electron/main.mjs#L229)
3. **提醒与业务分工独立。** Worker 继续向 Homer 回报，Homer 沿现有授权交付、提问和升级审批。偏好、焦点、提醒和点击由宿主处理，LLM 继续接收原契约规定的用户输入、实际答复及业务事实。配对手机继续沿 WebRTC 同步和前台补读，聊天渠道按原请求或获准的事项订阅外送。首版范围是本机桌面系统提醒。 [主 Agent 与 Worker 会话](main-worker-chat-architecture.md) · [移动消息同步](mobile-device-pairing-architecture.md) · [原请求与事项订阅](multi-channel-architecture.md#1-首版范围与消息路由)

## 验收计划

| 层级 | 应取得的证据 |
| --- | --- |
| 宿主离线 | 核对普通回复、纯附件、本地后台交付、人工审批和提问在提交或待办生效后才产出候选。覆盖回滚、流式片段、内部回报和自动审批。同一待办的卡片与关联说明先后到达只算一个事件，同事项两个独立待办各算一个。 |
| 桌面隔离 | 验证四种开关组合、后台、前台入口可操作或被挡、前台卡片渲染延后，以及启动首条实时事件。刷新和重连不补弹。点击覆盖原消息、待办不在首批 80 条、暂时断线、已处理或撤销、跨事项错配，以及草稿和答复回执保留。 |
| 实际安装包 | macOS 签名包与 Windows NSIS 分别验证授权和拒绝、偏好重启后保留、勿扰、锁屏文案、最小化、关窗语义与进程运行时的通知中心点击。 |
