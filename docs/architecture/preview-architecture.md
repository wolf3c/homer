# Homer Preview 架构

本文是 Preview 的架构入口，汇总当前职责、来源规则、已知故障、拟议变更与验收状态。专题设计继续记录业务细节，历史报告继续保存各自版本的结果。

## 当前职责与能力

Preview 是主聊天旁的查看界面。用户可以查看从消息和事项打开的内容、切换标签、下载支持的文件，以及对有稳定来源的内容做批注或引用。宿主拥有消息、权限、附件和定时记录。文件阅读器消费获准内容，Electron 管理原生网页及其操作者，Composer 管理批注和引用草稿。

| 能力 | 已实现的源码行为与边界 |
| --- | --- |
| 文件呈现 | 成果附件通过消息、资产和版本读取，支持文本、Markdown、图片、音视频、PDF、HTML 和补丁。补丁按文件内容呈现统一差异，异常或过大时提供原文或下载。聊天气泡中的媒体另有按需读取。 |
| 本地链接与交付附件 | 桌面本地链接应读取原路径的当前文件，历史消息仍需源消息及原路径有效。已确认的交付附件读取固定快照，配对移动端通过宿主读取该版本。0.1.21 安装版的本地路径入口存在下节记录的网关缺口。 |
| 文档相邻资源 | Markdown 附件正文为快照，相邻图片从保存的原目录取当前内容。原文档改动不改变解析基准，无可信原目录时显示缺图。HTML 附件相邻资源有独立的目录和类型限制。 |
| 原生网页与 HTML | 桌面用隔离的 WebContentsView，页面拥有独立的 ID、文档代次及操作者。Agent 可按授权操作自己的后台页，用户接手后使用同一页面。网页导航保持原来源，历史引用另存捕获位置。非原生 HTML 使用沙箱渲染。0.1.21 的用户打开入口存在下节记录的网关缺口。 |
| 标签、批注与引用 | 标签用于选择和关闭，内容工具栏显示当前来源并提供适用操作。支持的图片、文档文本和网页批注沿 Composer 草稿保存。普通本地路径不自动成为有固定版本的附件或批注来源。 |
| 定时任务 | Preview 容纳只读定时任务列表和详情，可把来源引用到 Composer。调度、权限、执行与恢复由定时任务模块负责。源码及隔离展示证据见专项，不能据此确认每个安装包的网关可用。 |

### 对话中的定时任务详情

对话用时钟图标和单行标题标识定时来源。宿主只从同会话、经授权且有确认回执的当次投递派生标题。计划 ID 可核实时，点击标题直接打开与定时中心共用的只读详情，按当前权限读取当前计划。旧消息保留当次标题，无法核实 ID 时显示静态标题，详情读不到时明确提示。

定时标题沿用普通事项标题的字号、行高与气泡间距。触屏点击区域独立于标题排版。隔离 Chrome 在 1100 和 390 CSS px 验证了两类标题的文字下缘到气泡上缘均为 6 px、触屏命中及相邻气泡、单行省略、详情入口和焦点返回，以及计划缺失、拒绝读取与断连时的表现。历史来源另用临时 SQLite 验证。安装版和移动真机待验。

### Preview 顶栏开关

主顶栏「预览」和 Preview 右上「收起预览」共用 44×44 CSS px 点击区域、18×18 图标、透明底色和悬停背景。两处按钮距所属顶栏右缘 8 CSS px，并使用内收的键盘焦点线。隔离 Chrome 以 1440、801、800、390 和 320 CSS px 验证尺寸、对齐、鼠标和键盘开关、焦点返回及标签和内容恢复。安装版待验。

## 入口与生命周期简化（2026-11-21）

**目标是让用户点击消息中的链接，就能打开现存且获准读取的文件。** 复用现有消息、附件、桌面网关和阅读器。由宿主确定来源和读取语义，由阅读器展示已确认的内容，由标签管理当前显示位置。沿用已有消息关联和媒体记录，无需新增持久化状态或批量迁移历史。

### 已核实的故障

- **0.1.21 安装版的首个断点在真实桌面网关。** Electron 经 `desktop-runtime.mjs` 启动 `scripts/dev.mjs`。安装包的网关没有提供 `readMessageFile` 或 `openPreview`，`dev-host` 也没有分发这两个操作。按安装包的桥接能力隔离复测，桌面认证有效时，本地文件入口返回 `403 message_file_scope_denied`，网页及原生 HTML 入口返回 `409 preview_unavailable`。缺桌面认证返回 `401 web_desktop_auth_required`。已接通的 `media.read` 与 Agent 网页工具各自走原通道。
- **补上网关后还有定稿身份切换。** 同一个 `hero-command.webp` 链接在定稿前属于原生过程消息，发布 `request-final` 后出现在正式回复。旧标签保留打开时的消息 ID，重试仍用该 ID。用安装版服务层和真实记录隔离验证，旧 ID 返回 `409 message_file_scope_denied`，正式回复 ID 返回 `200 image/webp`，字节摘要与原图一致。这张图没有交付快照，桌面读取的是原文件。未捕获截图当时的请求体。两次隔离验证分别覆盖缺桥接与服务层身份校验。

### 打开请求与来源判定

桌面 Markdown 点击保留原始链接目标和所属会话、消息 ID。DOM 中补全的 `href` 只用于正常网页导航。宿主用同一个解析规则匹配可信消息正文，仅接受同线程当前可见、未撤回的来源。前端可以使用已加载的成果标题和类型提示，分页缓存里的附件清单不能决定改读原文件。保持已有入口和 ID，在网关内共用明确列出的操作契约和分发类型。

| 来源 | 宿主处理 | 平台与历史行为 |
| --- | --- | --- |
| 消息中的桌面本地链接 | 先确认消息、链接及是否存在已确认的交付映射。没有交付版本且链接可走本地读取时，打开原路径当前字节。复用规范路径、受保护路径、普通文件、链接、大小及读取前后一致性校验。 | 同一历史链接可重新打开，修改后的原文件在重读时生效，删除或受限时显示对应原因。桌面权限继续由可信窗口和本地网关验证。 |
| 成果按钮、交付链接与显式附件引用 | 复用消息、`assetId/revision`、读取资格及摘要校验。已确认的交付映射指向固定版本。映射存在但版本丢失或授权失效时，直接报告该状态。 | 桌面和配对移动端读取相同版本。原文件被编辑、移走或删除时仍可读已交付快照。仅桌面有效的路径在手机端提示需要交付副本。 |
| HTTP(S) 网页与 HTML 成果 | 保留网页来源校验及 Electron 隔离会话。宿主确认后的内容类型决定是否打开原生 HTML，原生页仍通过已授权的附件协议读取并核验摘要。本地 HTML 路径及非原生 HTML 沿用相应隔离渲染，保持各自资源访问边界。 | 原生页的进程内 ID 随运行期失效。历史引用按已存的消息、请求或附件来源校验后重开。网页权限、页面代次、操作者、用户接手及操作回执继续由原生宿主管理。 |
| 补丁及其他文件格式 | 文件先按其原有来源获准读取，再由阅读器根据已确认的 MIME 和文件名选择呈现。补丁复用 DiffViewer、大小和行数限制以及原文和下载回退。 | 补丁没有独立权限或恢复机制。文件改动摘要另有归属契约，不能由预览中的补丁推导。 |

定稿前可验证当前公开的原生最终答复片段。定稿后，若旧 ID 来自这条回复关联的过程消息，宿主沿已有 `replyMessageId` 和已确认的正式发布记录定位正式消息，再校验同一个 Markdown 目标。未确认发布、跨线程、撤回、目标被删改或正式正文中无该链接时，旧标签不能获得读取资格。禁止按文件名、目录或全文搜索补配来源。重试从已知消息和原目标重新解析，避免继续绑定过时的展示 ID。首次稳定打开和刷新使用同一套规则。

继续保留 Markdown 附件正文快照与相邻图片的既有语义。相邻图片经原记录所在目录和 `media.read` 取当前内容，已有移动端资源适配仍可读取经宿主授权的资源。无可信原目录时保留缺图结果。HTML 相邻资源仍受 HTML 附件目录和类型限制。

### 标签与阅读器

文件标签保留待解析来源、选中项和返回焦点，成功后使用宿主确认的来源继续读取和引用。文件读取、下载和批注按实际版本工作。旧读取在切换标签、关闭面板或切换线程后不能覆盖当前内容；保留网络取消、Blob 回收及草稿保存代次校验。

Electron 持有原生页面的创建、清单、关闭、导航和文档代次。前端从这份清单投影浏览器标签，打开回执或 `onShow` 只表达选中意图。页面清单刷新和打开回执都用同一个页面 ID 对齐。隐藏面板只隐藏视图；关闭失败或未确认时先读取页面清单核对，避免重放未知操作。去除同一 HTML 同时占用文件标签和原生页面的双重状态。现有 `webSource` 网页 iframe 分支只有测试夹具显式传入，删除前仍须核对真实入口、旧引用与非原生 HTML 沙箱的独立覆盖。

### 分步实施与失败恢复

1. **修复真实接线。** 保留 `/api/preview/message-file`、`/api/preview/open` 和 `/api/media` 的兼容入口，在现有网关和子宿主的窄操作清单中接通已有处理。沿用媒体传输模式处理二进制，核验大小、MIME 和文件名在跨进程往返后保真。缺少桥接能力采用可诊断的不可用结果，权限错误保留原意。只读请求可由用户重试；页面打开或关闭结果未知时先查状态，升级期间不自动跨宿主代次重放。
2. **收敛来源判断。** 先落地定稿身份与附件映射的服务端规则，再移除前端从部分历史清单推断读取方式的逻辑。保留历史消息、历史附件和批注引用原格式，用双 ID 真实关联兼容已打开的标签。继续验证旧绝对路径、`file:`、Windows 盘符、编码空格和 Unicode，以及现有保留路由。
3. **收敛显示状态。** 原生页面和文件标签各用现有数据来源，面板统一选择和焦点，确认 MIME 后分流。迁移到真实入口验证后再删除重复的 HTML 打开分支及无生产调用的网页 iframe 分支。保留其他平台的 HTML 沙箱和历史来源重开测试。

### 验收条件

| 范围 | 必须观察到的行为 |
| --- | --- |
| 安装版真实点击 | 从隔离的打包桌面实例点消息链接，经过真实网关及子宿主收到图片字节并显示。普通网页与 HTML 附件各完成实际原生打开。用正常指针或键盘交互，记录响应与显示结果。 |
| 定稿、历史与权限 | 流式阶段点开链接，定稿后在原标签重读，再从历史重新点击。验证同一获准目标仍可读，撤回、跨线程、改换目标、受保护路径及未经认证的调用均拒绝。校验文件修改、删除与恢复。 |
| 快照及移动端 | 同一交付版本在桌面和配对手机保持摘要一致。覆盖原文件变更或删除、版本失效、未交付的本地路径、Markdown 相邻图片及历史重开。使用隔离配对进行专项，真机结果单独记录。 |
| 标签与格式 | 验证 HTML 仅有一个标签和原生视图；切换、隐藏、关闭和重开时显示与焦点一致；延迟读取及批注保存不能串到新标签。检查有效补丁和回退、HTML 隔离及用户接手后禁止 Agent 写入。 |

**首轮已实施于源码。** 桌面网关与子宿主接通本地文件和网页打开。已有交付映射时以固定版本为准，缺少版本时拒绝读取。需用旧过程 ID 重读时，经已确认的发布记录定位正式消息，并核对两端正文中的同一链接。用户打开慢网页先取得页面 ID，加载状态沿用原生页面清单。配对移动端继续使用原有附件读取，原生网页打开保持桌面专用。

复审补齐了慢页显式地址的去重。页面导航完成前按正在打开的地址识别重复请求，完成后恢复按页面当前地址处理。原生回归在服务器尚未响应时验证普通点击只显示一个标签，并核对显式地址重复打开返回同一个页面 ID。

验证覆盖 56 项定向测试、前后端类型检查及隔离 UI 构建。用安装包自带 Node 启动当前源码的真实桌面网关和子宿主，配合合成 Codex 验证本地文件读取返回 200、未认证返回 401，以及网页打开到达原生 IPC。移动端另用隔离 WebRTC 验证附件字节传输、配对与设备撤销。独立 Electron 的本地文件点击、慢页、HTML 附件及用户接手等功能断言通过。系统整窗捕获未产出图片，即使 Electron 报告录屏权限已授予，原生截图专项仍退出失败。新安装包与手机真机待验。完整的标签生命周期收敛和旧 iframe 分支清理留待后续。

## Preview 更多操作

**已接入桌面源码。** 离线 Demo 在 1200、390 和 320 CSS px 验证了菜单布局、键盘与焦点、固定版本及导航后地址。

在当前内容工具栏右侧显示「更多」，仅在有可用操作时显示。沿用现有标签与来源，菜单根据当前内容和设备决定，无需新增标签类型或持久化数据。

| 当前内容 | 桌面菜单 | 操作目标 |
| --- | --- | --- |
| 消息里的本地文件 | 「在 Finder 中显示」或「在文件资源管理器中显示」、「用默认应用打开」 | 已获准读取的当前原件。将现有系统定位扩展到可预览文件，保留无法预览时的正文定位入口。默认应用打开仅用于受支持的普通文件。 |
| 交付附件 | 「下载」、「用默认应用打开」 | 当前查看的固定版本。复用下载动作并将桌面附件的下载入口放入菜单。打开时交给默认应用的是该版本的独立副本。 |
| 内置网页 | 「在默认浏览器中打开」 | 当前原生页导航后的有效 HTTP(S) 地址。系统浏览器使用自己的登录会话。 |
| 定时任务 | 隐藏 | 沿用卡片上的详情和引用到对话。 |

本地 HTML 与直接交付的 HTML 分别沿用原件与固定版本的操作。相邻资源由父附件授权读取，但仍是相邻原件，首版隐藏新增文件操作。原生 HTML 视图实际导航到 HTTP(S) 网页后，按当前文档判断网页操作。内部 `homer-preview:` 地址、空白页和错误页没有外开入口。临时网页仍依赖源服务可达，临时原件消失后提示失效。配对手机沿用附件「保存或分享」和普通外链的系统打开，手机 App 单文件保存上限为 8 MiB，传输另受连接限制。只有电脑路径时提示到电脑端查看。 [原生页面载体](../../packaging/electron/preview-pages.mjs) · [移动保存](../../ui/file-download.ts) · [移动外链](../../mobile/App.tsx)

### 交互与宿主边界

- 复用 PreviewToolbar 和产品现有的 Base UI Menu 模式。菜单右对齐并限制在可视范围内，窄屏触控区至少 44×44 CSS px，网页导航可独占一行，标题按剩余空间省略。保留现有导航、批注、接手和权限入口。方向键与 Home／End 移动焦点，Enter／空格执行，Escape 收起并回到触发器，Tab 或点击外部离开。切换标签、关闭 Preview 或切换文档时收起菜单。
- 文件阅读器上的菜单可覆盖正文。原生视图沿用现有边界更新逻辑，让同一页退到菜单实际底边以下，收起后恢复原位。原生正文点击也收起菜单。菜单项采用原生按钮，键盘激活和指针点击使用同一可信事件入口。核对显示页和文档代次，避免迟到事件改变另一页的布局。 [工具栏](../../ui/preview-toolbar.tsx) · [现有菜单模式](../../ui/desktop-permissions.tsx) · [定位面板](../../ui/browser-preview.tsx)
- 本地文件定位与打开复用消息和路径校验，由用户从工具栏或无法预览时的定位按钮触发。系统交接前重新核对文件身份。默认应用打开限制在支持的文档及媒体扩展名，并拒绝常见可执行文件头。Finder 或文件资源管理器只提供定位请求回执，默认应用实际打开失败时显示错误。 [本地文件信息与定位](../../src/service.ts#L2512)
- 下载和打开重新读取当前消息、资产及版本并校验摘要。默认应用打开使用应用专用目录中的独立副本，文件名保留安全扩展名。副本至少保留 24 小时，启动和后续打开时清理过期目录。系统明确拒绝打开时立即清理该次副本。副本的编辑不回写交付版本。文件缺失、身份变化或系统拒绝均显示结果。 [附件读取](../../src/service.ts#L2495) · [现有下载](../../ui/file-download.ts)

### 最小实现

1. **沿用宿主读取资格。** 可信阅读器或隔离 preload 提交原始链接和已显示的来源，由宿主核对消息、附件版本或已登记的页面及文档代次。相对路径按宿主记录的源文档目录解析。仅接入以下现有资格，首版从原本已获准的文档打开一层相对文件。

   - **消息文件。** 用解析后的目标精确匹配同一来源消息中已单独交付或明确链接的文件，复用 `resolveMessageFile`。已有交付映射则读取固定版本，失效时显示原因。

   两条路径均沿用现有规范路径、软链、大小和读取一致性校验。同目录或文档内相对链接本身不授予读取资格。绝对路径和 `file:` 仅接受目标已有独立读取资格，远程网页不进入本机文件读取。无法核实目标时提示用现有消息链接或附件单独交付。
2. **沿用已有打开和显示流程。** 文档按宿主确认的文件类型交给现有阅读器，HTTP(S) 复用 `openBrowserPreview` 和现有原生页面。网页弹窗继续由 Electron 创建并登记，复用现有页面列表和显示通知。只为可确认的真人操作选中新页，切换、关闭或导航源标签后的迟到结果只保留后台页。单凭 `target`、弹窗回调或 DOM 的 `isTrusted` 无法区分真人操作与 `preview_act` 派发的 Chromium 输入。沿用现有标签保存来源和目标，刷新时重新校验，切换页面或线程后的迟到结果不能改变当前标签。关闭新页后原标签仍可切回。历史重开仅使用现有引用机制可重新验证的来源。

## 无法内置预览的文件（2026-11-23）

桌面消息中的本地 ZIP、超限文件和不支持的二进制文件显示名称、大小和原因。超过 50 MiB 的文件与扩展名为 `.zip` 的本地文件在读取正文前停止，已能从文件头识别的不支持格式只取短前缀。仍可能为文本的文件沿用有上限的判定。文件信息只包含展示字段，系统路径留在宿主。

### 当前规则

Preview 标签栏、网页工具栏与阅读区占位框属于宿主 React 文档。桌面在线网页和走原生路径的 HTML 内容由 Electron 主进程管理，作为独立的 `WebContentsView` 加入 `window.contentView`。宿主传入占位框矩形，主进程按缩放换算并限制在窗口内容区，只显示选中的视图。宿主 Portal、CSS `z-index` 与裁剪作用于宿主 DOM。原生视图有自己的排序、矩形边界和输入命中。

宿主查找带有布局矩形的 `[role="dialog"]:not(#canvas-panel,[data-preview-local-quote])`、`[role="alertdialog"]` 和 `[role="menu"]`。它未比较交叠、实际绘制顺序或模态范围。任一匹配会触发 `bounds:null`，主进程隐藏整个当前网页视图。预览卸载和空尺寸也会发送空边界。隐藏期间页面实例仍在，显式关闭才移除视图并关闭其 WebContents。恢复计算由页面切换、占位尺寸、窗口 resize、滚动、`body` 直接子节点增删及局部浮层标记变化触发。现有观察器没有逐帧跟踪浮层动画中的位置。

## 网页模态内的元素批注

**源码已实施，隔离 Electron 专项通过。** 只解决网页用 `<dialog>.showModal()` 打开弹窗后，Preview 能选中里面的元素，却看不到备注框或无法输入的问题。这里的「模态」是浏览器提供的 HTML 弹窗，不是系统窗口，也不是[宿主浮层使整个原生网页让位](#原生网页与宿主浮层2026-11-24)。普通页面、非模态 `dialog.show()`、自定义 CSS/Portal 弹窗维持现行为；**打开备注后保留选中虚线**另案处理，不纳入本改动。

### 为什么不只加大层级

当前批注运行时把一个 Shadow DOM 容器挂在网页 `body`，备注框已使用 `z-index: 2147483646`。隔离 Electron 把它加到 `999999999999999`，Chromium 的计算值为 `2147483647`，备注框仍不能覆盖模态或获得焦点。把 `popover` 单独挂在 `body` 也未解决；只移入带 `transform` 的模态虽能取得焦点，但固定定位的选框会偏移或被裁剪。这分别受 [CSS 顶层绘制](https://drafts.csswg.org/css-position-4/#top-layer)和 [HTML 模态交互范围](https://html.spec.whatwg.org/multipage/interaction.html#modal-dialogs-and-inert-subtrees)约束。

[Agentation 的容器实现](https://github.com/benjitaylor/agentation/blob/main/package/src/components/page-toolbar-css/use-feedback-portal.ts#L15)默认挂到 `body`，只在调用方指定容器时移动同一宿主并启用手动 `popover`。DOM 归属留在弹窗内，绘制脱离祖先的变换与裁剪。已核对 3.1.2 发布包；Agentation 并不替应用识别任意网页的弹窗。Homer 只需从已经命中的目标确定这一个容器，不引入该依赖。

### 最小改动

只改[网页元素批注运行时](../../ui/browser-annotation.tsx)。继续使用现有 `host`、Shadow Root、React Root、Base UI Popover 和备注表单，不增加 DOM 宿主、组件、依赖、IPC 或草稿字段。

1. **按目标确定作用域。** 悬停使用现有命中元素，编辑优先使用该条批注的既有元素引用；以实际目标的 `closest('dialog:modal')` 找同文档、仍连接的模态。仅使用现有拾取能确认的祖先，不按 DOM 顺序选「最后一个」弹窗，不泛匹配 `[role="dialog"]`，不跨 iframe 或扩大 Shadow DOM 拾取。编辑目标仍有效时，不因光标移到旁边就切换。
2. **仅在作用域变化时移动同一个 `host`。** 普通页面保留 `body` 和当前样式。进入模态时先结束旧的手动 `popover`，把 `host` 挂进确认的模态，再在该 `host` 上启用 `popover="manual"`。样式只在该模式生效：视口原点、零尺寸、透明、允许溢出、容器不吃指针，只有现有备注框和标号可交互。返回 `body` 时清除这些属性和样式；同一作用域不重复挂载或重新弹出，不重建编辑器。无 API 或目标中途失效时退回现有路径，不强行打开、关闭或修改网页弹窗。放进模态期间只绘制该作用域内的标号和历史框，避免把底层页面的标号一同抬到顶层；原批注数据不变。
3. **复用现有刷新和清理。** 用现有命中、编辑状态及 `open` 变化/子树移除观察来重算，不新增轮询或全局模态栈。上层模态使下层输入框失焦不是取消：保持草稿和原作用域，不切换到上层；上层关闭后，用户可继续原草稿，批注不主动抢回焦点。原模态关闭、目标被移除或不再属于原模态时，保留草稿原摘录和输入；若没有可用的原目标，则用现有固定回退位置，不重新查选择器绑定替代元素。这也适用于本页内刚保存的标号。暂时无命中的光标间隙不必反复移动仍有效的宿主。保存成功、显式取消、关闭批注和切页沿用原清理；同一页面内保存失败仍保留输入，旧文档回执不能作用于新页。
4. **备注使用现有定位组件。** 仅在新增的模态路径中，把真实编辑目标直接传给 Base UI 的 `anchor`，由现有定位组件观察内层滚动，不另做坐标换算。其他路径保留现有定位，原目标不可用时仍使用固定回退锚点。仅在同一输入框且所在范围仍可交互时尝试保留焦点，不主动抢焦点或解除网页的模态约束。

安全边界不变：仍在 [Electron 隔离世界](../../packaging/electron/preview-pages.mjs)运行，网页内容只是选区材料，批注输入与保存沿用可信输入、主框架校验、用户接手、文档代次和现有保存回执。移动容器不增加页面、附件或操作者权限。

2026-11-23 的隔离桌面验证使用生产 UI 和真实消息文件读取接口。验证流式时不请求本地原件、定稿后加载、权限拒绝、替换与删除、简短的缺图提示，以及普通链接和公网图。Chrome 正常退出，未强制关闭，无 watchdog。合成配对浏览器走真实 WebRTC 显示固定附件，并核对桌面路径提示。35 项服务及移动协议回归通过，含固定附件缺失不回退。复审在同时包含两个功能的隔离 Electron 验证了同一 PNG 换版后正文显示当前图、已发送批注仍显示原图以及不重绘不匹配的旧选框，进程退出 0。内嵌图读取在最多 512 字节的文件头即拒绝不支持的类型。正式安装版及配对手机真机待验。

### 实施前验证定位

真实定位使用隔离安装包和可信合成 HTTPS 页面验收。分别观察网页权限回调、电脑系统授权和定位提供方结果，记录只保留状态。Electron 45 的 Google 网络定位路径需要启用定位 API 的 Key 和关联结算账户。对应 Chromium 在 macOS 默认先使用系统定位，可回退到网络提供方。现有安装包与启动环境未发现 Google Key 配置，macOS 系统路径是否可用尚未实测。若需启用外部服务，先确认配置、费用和数据范围。

用 DevTools 定位覆盖和虚构坐标离线验证网页交互、允许与拒绝、重试和撤销。这个测试只验证权限链，真实定位另在授权的测试环境验证。核对当前安装包如何报告 `geolocation`、`geolocation-approximate` 及系统实际提供的精度。规则只匹配已验证的具体权限，近似定位的同意不能用于精确定位。使用模拟坐标通过的结果不作为定位服务验收。

### 宿主规则与 Homer 判断

1. **宿主先核对来源和站点规则。** 首版只接受可核实的 HTTPS 顶层页面定位。请求以 Electron 回调给出的实际来源、权限和宿主登记的页面、文档代次为准。Agent 页面从宿主记录核对当前所属会话、任务和运行版本，用户主动页面以会话和页面为准。权限检查和请求回调使用同一规则，命中站点授权时直接处理。来源不明、本地或附件 HTML、跨站嵌入内容不进入审批。
2. **Homer 只判断当前任务是否需要定位。** 后台任务使用原始用户目标、当前操作和可观察的阻塞，权限回调不等待模型。无需定位或证据不足时先拒绝，让页面继续加载，并将拒绝状态提供给当前任务。确实受阻时，说明原因和经该站点验证的再请求入口，例如点击「使用当前位置」。只有浏览器实际发出新的有效请求才呈现审批。若站点拒绝后不再发起请求，反馈阻塞和可用的手动继续方式，未知操作先核对再决定是否重试。
3. **新增授权由用户明确决定。** 有效任务确需定位时，Homer 提请审批。用户主动打开或已接手的页面由宿主直接生成审批，可只关联当前会话和页面。网页文字只供解释用途，等待、超时或断线均不生成授权。摄像头、麦克风、剪贴板和屏幕共享等权限不进入首版流程。

### 一张审批卡与站点撤销

左侧站点图标和原生网页局部让位已接入源码，隔离 macOS Electron 验证通过。实现与验收见[定位入口优化](preview-macos-location-permission-plan.md#工具栏定位入口优化2026-11-24)，下文为现行审批和站点授权契约。

需要用户决定时，桌面选中原 Preview 标签，在 Homer 工具栏显示等待状态和「查看审批」。对话复用现有审批卡，展示权限、请求站点、已知用途、关联任务（如有）和范围，桌面卡可定位原页。等待时暂停该页的 Agent 写入，审批状态独立于用户接手状态，结案时保留已有的用户控制。

卡片提供「允许本次」「记住此站点」「拒绝」。按次决定只适用于当前有效请求及其合并的回调。「记住此站点」明确告知后续按**浏览器配置、精确来源和具体权限**复用，包括该站点在 Homer 后台页面发起的匹配请求，直到用户撤销。精确来源包括协议、完整主机名和有效端口，子域和重定向目标分别核对。同步提供桌面查看与撤销入口，撤销后后续请求重新核对。已交付的坐标无法收回，已开始的持续定位能否立即停止单独验证。已记住的规则在当前浏览器配置中仅保存来源和权限类型。审批与移动消息不带坐标、完整登录地址或凭据。

已配对手机通过现有对话状态和答复通道处理同一张卡，在线桌面宿主将结果交回原页面。若电脑还需系统授权，提示在电脑处理。

复用审批组件、交互记录、回执和移动设备校验。新增 Electron 权限事件与决定回传，使用网页权限专用的请求和选择字段。实时回调由 Electron 持有，人工等待独立于短时 Preview 工具调用。

### 并发、失效与回执

- 同页、同文档、同来源和同权限的在途请求合并为一张卡。持有回调的宿主核验原页面、文档、请求和归属仍有效后，只落实桌面或手机的第一条有效决定。相同答复请求 ID 与选择返回原回执。
- 页面关闭、导航换文档、页面转交、所属任务停止、等待超时或宿主重启时，原待审批请求失效，仍存活的回调按拒绝收束。校验通过才交付决定或写入记住规则，迟到的选择不影响新页面、不留下站点授权。
- 手机断线期间桌面可继续处理，手机重连先查状态和原回执。区分「已收到决定」「已交给原页面」和「已失效」。交付允许后，定位结果仍取决于电脑系统和定位服务。

### 首版验收

1. **定位与任务判断。** 隔离安装包验证实际提供方和精度。合成站点覆盖无需定位时继续、拒绝后能或不能重新请求，以及没有关联任务的用户主动页面。
2. **站点规则。** 验证同页重复只出一张卡，允许本次、同来源后台复用、跨来源或不同精度不借用授权、撤销后重新核对，用户接手状态保留。
3. **跨端与失效。** 用桌面和配对真机验证定位原页、共享卡片、双端竞争仅落实一次、断线后核对回执。导航、关闭、超时、任务停止及重启后，迟到决定不生效也不留授权。

隔离 Electron 45.0.0 以本地 HTTPS 和虚构坐标验证了 `geolocation` 原生回调、拒绝后重新请求、同页并发、记住与撤销、原页提示及导航后拒绝迟到授权。另有 11 项对话与 Preview 定向用例和 12 项移动适配用例通过。近似定位的运行时回调、真实定位、打包后界面和配对真机闭环待验。Preview 内链接打开按其独立范围验收。
