## 用户如何使用

- 在「工作状态」点事项标题，以事项 ID 打开或选中 Preview 标签。同一事项重复点击复用原标签。列表正文显示事项标题及 Worker 数量，零 Worker 时只显示标题。行内引用和归档按钮各自处理自己的动作。
- 宽屏复用 Preview 分栏，左侧继续使用主对话；窄屏复用现有全宽 Preview，包括关闭、焦点恢复和安全区域。打开、缩放或收起分栏时，沿用主聊天锚点，以原消息及可视偏移保持阅读位置。切换 Preview 标签只切换右侧内容。
- 标签使用事项标题和「事项详情」入口。默认从最新处开始，复用气泡、时间、引用、附件及成果样式展示可核实归属的消息。一条消息明确涉及多个事项时，各自可看到同一条完整原文。长标题可省略，详情能读全。
- 往上滚动接近顶部时自动读取较早消息，并保留阅读锚点。首屏为空会自动开始查找，内容不足一屏时也可继续向上操作。每轮最多连续请求三次，找到消息或到达终点就停止。连续空页用完本轮次数时才显示「继续查找」。提示「仅显示可确认归属的消息，部分早期记录可能只在主对话中」。读取失败就地重试，已有内容保留。
- 「事项详情」在同一标签显示标题、当前事项内容、笔记和 Worker 清单。每个 Worker 的带标题分工以时间轴按派工顺序倒序展示，当前标题加粗，历史标题直接可见。现有分工记录用于确定顺序，界面不显示日期。缺少确认的分工标题时显示「暂无工作标题」。「返回对话」恢复事项内阅读位置。详情期间隐藏该标签输入区。
- 附件及成果开到单独的 Preview 标签。关闭文件标签优先回到打开文件的事项标签（仍存在时），也可直接点事项标签返回。点「在主对话查看」或跨范围引用才定位主对话原文；桌面保留右侧事项标签，窄屏先收起 Preview，重开后回到事项。主对话继续处理咨询、授权和队列；已完成的历史问答和授权沿用可见性规则。
- 事项阅读区独立纵向滚动，输入区固定在标签底部。切换视图聚焦标题或原触发点，避免浏览时弹出软键盘。触屏主要操作有 44 CSS px 命中区。关闭事项标签后可从工作状态重新打开并继续草稿。

## 发送和草稿

事项标签使用已有 TaskReference，默认显示带标题的固定事项引用；每次提交带当前已核验的事项 ID、版本和标题。主对话和事项标签显示同一条宿主确认的消息，原有引用块可继续定位事项。原文引用、附件和批注沿用原协议；跨事项引用保留来源，当前标签决定发送关联。主 Composer 仍按现有方式加入或移除事项引用。引用提供定位，具体办理沿用现有授权。

主对话沿用原草稿键。复用同一草稿结构，事项草稿按当前线程和事项 ID 定位，保留正文、引用、附件及上传 requestId。主对话和各事项可同时有草稿，切换标签、收起 Preview、关闭再打开均不互相覆盖。原队列编辑、业务答复、全局截图以及已有文件 Preview 批注向主草稿的入口保持现有作用域。从事项消息添加引用时使用该事项草稿。异步读写按发起作用域、requestId 和代次归属。

继续使用同一条主入箱和队列。线程级未确认记录和回执核对共用一个所有者；待确认项带原 requestId 和草稿作用域。失败恢复先核对作用域和清除代次，保护后来输入。版本或标题变化导致拒收时保留内容，读取最新事项后由用户核对并重试。结果未知时按原 requestId 核对。桌面入口的暂存回执不能确认主入箱接收；有宿主回执后才清理该草稿。用户可保留旧请求继续核对并另写一条。提交同时核验原线程与 readEpoch。断线保留草稿。归档沿用可引用和发送的原规则；引用不会自行恢复事项或启动 Worker。

## 现有数据与历史边界

先从当前获准的主线程读取原始消息、输入和已确认回执，沿用主对话的可见性、撤回及投影规则。宿主逐条核实归属，保留可公开的投影消息，再从保留的消息派生附件、成果、媒体和历史交互摘要；嵌套来源也需独立通过原有授权。主对话结果中的资源、过程与交互集合不能整体带入事项页。

| 记录 | 采用的关联 |
| --- | --- |
| 用户带事项引用的消息 | 已入箱输入保存的 `taskReference.taskId`。历史标题与版本照原记录显示，当前改名或换版不会让历史脱落。服务端已有提交校验；旧导入或缺记录时仍须核对原输入与同线程身份。 |
| 用户的原始交办、补充及明确派工触发 | 复用 `taskSourceRequestsSql` 中事项版本及 Run 的来源 requestId，再关联当前线程的真实用户输入和可见消息。仅证明该条输入有关；同一用户输入确有多个事项时可在各自显示。 |
| 已完成的事项问答 | 从原 responseUserMessageId 关联对应用户输入并核验同主线程，再按已确认的 Run、事项版本或请求来源关联。沿 host 的可见交互投影复用答复，未完成审批和实时咨询仍归主对话。 |
| 荷马的正式交付与归档消息 | 复用同线程用户可见的持久 `taskId`／版本或已确认的发布、归档来源。按主对话当前投影取原文和成果，不取归档摘要代替全文。 |
| 荷马普通回复及过程投影里的最终正文 | 沿主对话已核实的输入→回复／最终投影关系归入该次显式引用的事项，或复用 `withTaskSources` 中已验证且确实指向这条公开消息的底层来源。卡片只提示过程曾涉及事项，卡片缺失或流程卡出现均不能独立决定一句答复的归属。后者仅限该输入的实际答复，历史有独立明确事项时也保留各自关联；不得从一次派工的来源或整个相邻回合推导所有荷马文字。 |
| 其余旧消息和内部记录 | 标题、关键词、时间相邻、旧流程卡或 `taskSourceUnresolved` 无法证明归属。不能核实的关系不纳入；一条消息同时有已核实与未核实来源时，只使用已核实的关系。Worker 往来、仅内部可见的处理正文、撤回和不可读取内容遵循现有投影门禁。 |

普通请求最终落库时可以没有 `taskId`（例如 `request-final` 发布），因此只按助手消息的 `taskId` 会漏掉带事项引用后的普通回复。现有归档读取仅按部分已知来源提供最多 80 条摘录，`readTaskSummary` 也只有当前目标及单一来源提示。两者都不能直接作为此页完整历史。当前没有旧数据归属覆盖率的实测，也无法保证找回任何从未留下可靠关联、已清理或不可读取的消息。

## 最小实施

### 历史读取与刷新

在现有「/api/history/page」请求增加可选事项 ID，复用当前授权线程、readEpoch、历史位置和主投影。省略事项 ID 的路径及行为保持原契约。普通回复在输入与答复分属不同页时也应可归属：沿主投影的原始 requestId、replyId 或过程身份回查同线程输入，不依赖前端有无载入原消息。按稳定原消息 ID 去重并保留原展示顺序。复用现有成果来源校验，完成过滤后才派生允许返回的字段。 [历史入口](../../src/web-chat.ts) · [主投影](../../src/web-history-pages.ts) · [宿主投影及资源派生](../../src/web-homer.ts)

- **用扫描边界翻页。** 继续使用主历史有序单元定位。首版每次读取最多扫描三批现有历史页，命中一批即可返回。返回本次已经检查的区间和下一扫描边界，游标校验事项 ID、线程、readEpoch 和方向。即使零命中，非终点仍可继续。终点以底层历史耗尽为准，around 区分范围外、不可读与读取失败，分页不得按末条匹配消息重算，也不得因空页、请求失败或游标失效误判结束。视图内串行续读空页，主动定位和返回最新可以中止向上加载。扫描范围随历史窗口保留，供 revision 更新时重新核对。
- **用扫描范围替换刷新。** 复用现有 revision 信号刷新活跃标签，先同步最新段；对已加载的显示范围，按已扫描区间分批重新核对。按位置区间替换消息及派生结果，定稿换位置时对旧区间移除、新区间补入，覆盖新增、正文修订、定稿换 ID、撤回、附件变动和归属校验结果变化。相邻范围有同一原消息时按原 ID 去重，删除只作用于这次确认扫描过的范围。空结果可以有效移除该区间的旧匹配；增量按 ID 合并无法表达这类删除。现有 HistoryWindow 的更新主要保留已加载行，复用位置和去重逻辑时给事项范围补上替换语义。 [历史窗口](../../ui/history-window.ts)
- **保留阅读位置。** 向上分页或刷新前记录容器、原消息 ID 和可视偏移。锚点被移除时选最近仍可见消息；在底部阅读时保留贴底规则。较旧 revision、旧标签或旧 readEpoch 的返回不得覆盖当前窗口。失败保留现有窗口与草稿，可重试或重读最新段。

### 气泡、定位与标签

在 PreviewTab 增加事项分支，以线程和事项 ID 复用标签。现有标签切换会卸载内容，阅读位置及详情模式由标签外的现有 Preview 所有者保存，折叠和重开均可恢复；显式关闭后释放该标签的加载窗口，草稿仍按原作用域保留。打开文件时在文件标签的 UI 状态记录来源事项 ID，关闭时若来源标签尚在就选回它，否则沿用现有相邻标签规则。详情消费现有事项数据的标题、goal、notes 和 workers，可沿现有位置及读取刷新。首屏使用列表中已有 OverviewTask，按事项 ID 刷新相同投影。详情复用按已受理派工顺序保存的 assignments，复制后倒序展示，首条标为当前。只有 workTitle 时沿用该标题，两者均缺失时提示「暂无工作标题」。 [Preview 标签](../../ui/canvas-panel.tsx) · [事项数据](../../src/task-overview.ts)

复用 UserMessage、AssistantMessage 下的气泡内容及其引用、时间、附件和成果组件。主聊天的 VirtualMessage、主运行状态、队列和审批交互继续由主界面持有。若气泡当前依赖 assistant-ui 的消息上下文，抽出按已投影消息传参的共享渲染层，让两处适配各自容器，避免复制主聊天或把 Preview 挂入主列表索引。过滤后的成果资源随事项阅读上下文传入，Markdown 交付链接仍按原消息和目的地匹配；本地文件、成果和原生 HTML 打开时均记录来源事项标签。事项内原文已加载时只滚动事项容器；未加载时先用同一宿主读取的事项范围定位。确认目标在范围外且主对话仍有权读取时，才走现有主对话 around 定位。原文已撤回或不可访问时保留引用摘录并提示。显式「在主对话查看」直接调用原主对话入口。滚动、焦点及文本选区只查选定容器；同一原消息可在左右同时渲染，DOM 标识按容器区分。 [气泡、定位与标签状态](../../ui/homer-app.tsx)

### Composer 与消息所有权

提取普通 Composer 的编辑、校验、草稿与附件绑定，主对话继续装配既有队列编辑、待答和停止功能，事项只装配普通输入。每个可编辑作用域拥有各自 runtime、草稿键和附件 adapter 上下文。上传、删除和恢复捕获原线程、事项、requestId 及编辑代次，不以返回时选中的标签决定目标；草稿仍存在且匹配时才回写旧作用域。默认事项引用来自当前已核验事项，草稿本身与事项 ID 绑定。当前 MainComposer 的恢复标记、批注 owner 和 pendingKey 绑定主线程，直接挂第二个实例会争用。 [现有 Composer 与发送](../../ui/homer-app.tsx)

把现有提交和回执核对保留在主线程的单一所有者，通过原 prepareMessage、sendInput、主入箱和队列流转。已受理但尚排队的状态沿用主队列；事项历史消费同一个获准发布的消息事实，保留原 ID、原引用和原成果。失败恢复按原提交快照与草稿代次核对，避免覆盖后写草稿。明确拒收 task_reference_stale 时保留原草稿及上传绑定，重新读事项后由用户主动核对重试。无新增持久业务实体、事项线程、第二队列、历史回填或专用发送端点。

## 审核与验收

已确认的合成 Demo 在隔离 Chrome 1440／390／320 CSS px 通过 81 项原型检查，包括 54 条历史分页、双视图原消息、主对话锚点、草稿隔离和文件标签返回。原型证据只覆盖交互。产品精确候选通过两端类型检查、独立 Vite 构建、101 项离线检查、1440／390／320 CSS px 共 76 项正式组件检查。Chrome 正常退出，未强制关闭，无 watchdog。独立复审已确认初轮发现得到修正。验收范围如下：

| 验收 | 必测事实 |
| --- | --- |
| 宿主临时库 | 显式引用后的普通答复和最终投影跨页归属；明确多事项及历史版本；同名、跨线程、撤回和未核实旧记录均不误收；正文为空但附件获准的消息可读，过滤掉的行无派生资源。 |
| 历史与回执离线回归 | 稀疏空页可推进，终点准确；重读同区间能删除撤回消息和旧成果，旧响应不能恢复它们；主与事项、多事项的草稿／附件隔离；明确拒绝可恢复，未知只查原 requestId，成功仅消费一次。 |
| 隔离界面 | 桌面并排、390／320 px 全宽；上滑自动加载、阅读锚点、空首屏三次扫描上限、取消与失败重试；打开、切换、关闭的主阅读位置；同屏重复原消息的容器定位、跨范围跳主对话、附件标签返回、详情往返；两处输入含中文输入法和键盘操作。 |

实际旧库可归属的比例尚无实测。安装版、原生 HTML 文件打开、配对手机真机 RTC、系统输入法实机及真实荷马会话待单独验收。原生 HTML 标签返回与 RTC 提交范围已按源码复核。
