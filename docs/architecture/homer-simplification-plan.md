# Homer 后续简化实施方案

> 按独立验收单元实施和审核。使用 `superpowers:executing-plans` 或 `superpowers:subagent-driven-development`，每项通过后再决定是否纳入下一版。

**目标**　让用户能少交代、少等待，Homer 能沿原任务继续工作。把 Codex 已有能力交回原生路径，只保留 Homer 办理事项、协调 Worker 和交付所需的行为。

**架构**　Codex 负责执行、原生会话、工具发现和调用。Homer 维护任务要求与版本、Worker 协调、用户来源、消息附件及业务回执。桌面、Web、移动端和渠道各自处理入口与传输，沿相同的业务受理和交付契约接入。

**技术与基线**　审查基线为 `main` 的 `cbe9356`，使用 Node `22.22.0`、固定 Codex `0.163.0`、现有 SQLite 和 Electron。`65d49a4` 之后的精选工具清单更新仅修改按需查阅的资料。已核对的条目在下文记录结果，后续按验收单元推进。产品契约见[主 Agent 与 Worker 会话架构](main-worker-chat-architecture.md)和[测试边界](../testing.md)。

## 1. 从现状继续精简

- 任务表和原生 Worker 会话已经接通。普通回报沿消息保存，文件按地址或准确附件转交。保留任务版本、Run、操作回执、来源和进程退出证据，分别承接改要求、并发续办、未知副作用和迟到回报。
- 旧 HOME 业务执行分支、通用目录名单、`capabilities` 包装和普通 `$skill` 的宿主解析已退役。保留专属 `CODEX_HOME`、无模型轮次的 `controlOnly` 和绑定原请求的审批。归档 Skill 继续按真实归档事件选择。
- 首启第一版只停止了自动创建，旧排队输入仍可能执行。`4aa2612` 补齐了退役，2033 项默认测试和合并后 82 项定向回归通过。隔离 macOS 候选 `a9ddfb0` 使用实际 ChatGPT 验证首启零模型轮，仅取消从未领取的旧输入，未知回执不重放，普通排队消息沿原线程执行一次。两次正常重启共观察到五次原生续连，均使用原线程，四个显式模型轮各执行一次。旧首启沿现有回执办理，已达到结项条件。
- 附件原字节导出、既有 SILK 下载和播放、媒体引用与回收、状态栏的任务与执行区分均保持现有契约。媒体维护继续等原执行归属确认。归档后回收依旧由归档 Skill 和现有授权决定。

评估重复时先看记录由谁负责、什么时候需要。任务和版本记录用户目标，Codex 的线程和轮次记录会话，Homer 的 Run 记录派工归属与执行退出。输入受理、模型收到消息、用户收到交付是三个不同的事实，分别用已有消息与回执核对。可删除的是同一事实的重复保存或读取。源文件、可下载快照和已外发附件也各有用途，按实际保留引用判断。

## 2. 顺序、约束与审核重点

| 优先级 | 验收单元 | 实施门槛 |
| --- | --- | --- |
| A 已验 | 普通主轮的原生准备与续连 | 保留原生准备调用，省去新 Main 已采用变更后的多余续连。 |
| B 更新前 | 正式桌面资料兼容与收件 | 下次桌面更新前优先验证 B1。B2 独立核对持久受理，B3 仅删除正式包确定用不到的入口。 |
| C 独立小项 | Worker 会话、目录和主轮收尾 | C1 至 C3 可独立验证。C4 先核对模型所用字段，C5 先核对授权内工作是否因提示词被阻塞。与 A 同时开展时串行合入 `src/service.ts`。 |
| D 证据驱动 | 重启续聊、消息回执和历史读取 | 分别验证替代路径。历史桥、领取证据和外部读接口均需确认实际消费者。 |
| E 分项选择 | 外围能力、历史工具入口和原生选项 | 可删小项与产品取舍分开交付。需要改变权限或用户可见行为的项目先完成专项对照。 |

每项先写清能删掉的调用、字段、状态或分支，以及需要保住的用户行为。优先扩展原行为测试，先复现旧行为，再做最小修改和复验。复用现有标识、记录、回执、MCP 和审批入口。若收益依赖新增常驻监控、第二套状态或兼容协议，先保留现有路径。执行者、用户来源、工具调用身份仍由宿主绑定。提交、合并、真实账号验收及发布按后续授权办理。开发使用隔离资料与测试 HOME，保留其他工作和日常数据。

审核时逐项核对以下容易遗漏的情况。

- 刚移除或禁用的 Skill，以及原生 CLI 写入的 MCP 配置，下一适用轮应采用正确状态。项目切换要按目标目录读取配置。
- 同一个数据库格式的桌面升级应能打开原资料。真正不支持的格式、未知原执行者和冲突线程应在业务写入前明确拒绝。
- 一条消息在网关写入前后、业务提交前后或响应丢失时，均能按原 ID 查清状态。已提交和效果未知的操作不重复执行。
- Worker 第一次收到完整要求。补充、改口或更换执行目录后，仍采用实际版本、原用户来源和正确附件。授权充分时直接办理，有实质疑问或用户要求先审时走原待答。仅文字任务不产生每次执行的输出目录。
- 普通重启、切换模型来源、资料接管分别验收。原线程、原回执、已持久的用户消息、原字节附件及未知回执依赖的文件继续保全。

## 3. A · 普通主轮的原生准备与续连

- [x] **A1 固定引擎基线。** Codex 0.163.0 的普通主轮依次执行 `config/read → config/mcpServer/reload → skills/list → config/read → turn/start`。预热后 50 轮，准备 p50／p95 为 12.10／13.97 ms。合成回环另核对 Skill 新增、启停、删除、同名消歧及本地插件安装卸载、MCP 实际调用、项目切换与登录通知。耗时限本机对照。
- [x] **A2 保留四次准备 RPC。** 省略强刷时，刚删除的 Skill 仍可见。复用较早的配置读取时，漏掉在两次读取之间新写入的保留端点声明。省略重载时，项目 MCP 仍访问旧端点。按配置层版本去重虽然通过本地对照，但合成组织的托管 MCP 要求可在可见配置和层版本不变时改变实际调用结果。由 Codex 继续应用托管要求。0.167.0 同来源可续聊，但会拦截切换来源后沿原 ID 续聊，继续固定 0.163.0。
- [x] **A3 由刚启动的 Main 采用启动前已知的原生变更。** 新引擎启动并确认原线程后，只清除开始启动前已知且期间未变化的续连标记。启动期间或启动后到达的通知仍要求刷新。取消与成功可能竞态，无 ID 的成功也可能代表真实外部登录，因此保留这些通知的处理。去掉无人读取的 `nativeDirty` 字段。主轮终态后的后台终端查询保留。
- [x] **验收。** 55 项定向测试通过，隔离目录的 `npm run check` 完成构建、类型检查与 2036 项默认测试。固定 Codex 0.163.0 隔离回环对照确认，启动前通知、启动后通知、随后无新通知的三个首轮前续连次数分别为 0、1、0，沿用原线程。启动在途通知由宿主定向测试覆盖。账号通知为合成，未重新授权真实账号。登录重复和项目切换合并需要可验证的原生采用证据，当前没有必要增加记录或去重缓存。

入口见 [Homer 主轮](../../src/service.ts)、[原生刷新](../../src/engine.ts) 与 [宿主账号回归](../../tests/native-account-service.test.ts)。

- [x] **验收。** 35 项资料与接管回归、13 项 macOS ARM64 打包运行时回归通过。旧包创建合成资料，写入不同源码散列的标记后旧包拒绝，候选沿原线程读取旧消息、接续新消息，标记字节保持不变。已交付附件重启后下载摘要一致。schema 5 在引擎启动前拒绝，库字节不变，活动或未确认的原所有者仍被拒绝。macOS 采用本地签名候选和合成账号；Windows 与实际账号未在本项重跑。

### B2 · 保留桌面提交前的持久受理

- [x] **隔离对照。** macOS Electron 候选暂停业务宿主后，桌面请求收到 `202 gateway_stored`，业务库没有该请求，网关库完整保存原消息。恢复宿主后业务只执行一次。另一条消息的 HTTP 响应未交给聊天界面，按原 ID 查到已受理，同 ID 重试返回原回复 ID。正常重启沿原线程，页面回环 origin 和会话存储均发生变化。
- [x] **取舍。** 网关暂存和业务回执分别证明收到原输入与已提交业务，去掉前者会失去提交前唯一跨进程保留的原消息。配对手机的 WebView 也复用该聊天组件和网关提交，客户端未确认项同样使用 `sessionStorage`。保持桌面及开发路径、更新停止栅栏、旧日志与启动保护；暂缓直写及自动处理旧日志。现有受理回执只按请求 ID 展示状态，不能直接证明旧日志载荷等同已提交正文、附件和引用。
- [x] **边界。** 合成账号的真实 macOS 窗口测试覆盖网关先落盘、业务恢复、隐藏响应和重启；旧待投递行的启动拒绝由 B1 打包回归覆盖。配对手机本轮核对了实际调用链，未在真机重复故障注入。将来有稳定的原输入保全入口时再重评，不为移除一次写入另建存储。
