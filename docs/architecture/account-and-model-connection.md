# Homer 账号与模型连接

更新：2026-11-13。荷马来源沿用普通 New API 用户及每位网站用户的有限额度原生 Token；ChatGPT 来源的本机角色配置见下节。

用户在系统浏览器登录 yezi2，Homer 自动接收本人模型 Token 和运行配置，正常重启后生效。主 Agent 和 Worker 直接访问网关，设置里展示个人 Token 额度。

2026-11-03：删除开发阶段手填 Token 的桌面实验入口和日常版默认模型分支。荷马来源仅采用网站授权交付的账号与配置，充值使用该网站账号原有的 Token 映射。仅含 Token 的测试文件不再作为有效连接，不查询其余额，也不迁移或删除；网站授权成功后才原子保存正式连接。授权取消或失败保留原文件，应用继续沿原安全停止与重启流程，不改变历史、主对话和 Codex 登录。本机原测试连接是否已完成网站授权须单独核验，源码通过不代表账号已对齐。

- yezi2：网站身份、网站用户与 Token 的私有映射、一次性授权码交付和运行配置。
- AMH：一个专用普通归属用户，复用原生 Token、模型、价格与计费；共享用户需有足够额度，每人的 Token 仍有限。
- Homer：本机秘密、subject 校验、角色配置、个人 Token 额度及原有历史数据保全。

暂不自动充值，不建设设备 grant、每人独立网关钱包、充值去重表或内部 Homer API。购买保持关闭。

详细边界见 [MVP 需求](../33-account-payment-model-gateway-requirements.md)；源码改动及验证见 [原生 Token MVP](../2026-10-29-homer-native-token-mvp.md)。三方接口只采用 yezi2 维护的 v1-r5 合同，旧合同和旧联调结果只作为历史。

网站向公开配置接口和 PKCE 兑换返回同一套经过校验的配置。主 Agent 与 Worker 各自声明运行参数。字段、取值和能力校验见[会员配置契约](../2026-11-04-membership-context-config.md#通用边界与能力)。

## ChatGPT 模型设置（2026-11-11）

「设置 → 账号 → ChatGPT 套餐」分别配置 Homer（内部 `main`）和 Worker。产品默认值集中在 `src/model-config.ts`：Homer 为 `gpt-6.1-terra / high / priority`，Worker 为 `gpt-6.1-terra / xhigh / null`。CLI 默认值、荷马服务的角色合同及首次登录欢迎页保持原职责。

现有私有 `desktop-profile.json` 增加可选 `chatgpt`，按 `main / worker` 保存完整的 `{model, effort, serviceTier}` 覆盖。等同产品默认的角色不保存，全部默认时移除该字段。切换来源保留另一来源的配置，不迁移资料、不新增文件或表。运行配置中的 `serviceTier: undefined` 沿用原 `fast` 语义，`null` 明确清除加速档，字符串采用原生档位 ID。

现有账号桥的 `nativeModels()` 返回保存值、产品默认值和权限过滤后的目录；`applyCodex(roles?)` 有参数时只接受完整两角色草稿，无参数保留原来源切换行为。它们沿 Electron、desktop runtime、dev-host、service 和原生 control 管道传递。宿主只允许可信主窗口、限定接口参数个数和字段，不提供任意 RPC。目录通过 `model/list` 读完分页并排除隐藏模型，合并 `configRequirements/read` 的速度限制，只投影模型 ID、名称、深度、默认深度及服务档；不向界面转发原始账号响应、邮箱或凭据。

速度须同时得到模型和账号许可。原生 `planType: promax` 对应 Pro $500；现有明确的企业按用量／自动化套餐标识还须管理员显式允许 Ultrafast。未知、旧式企业／教育标识不据名称推断资格。原生权限不能确认时目录读取失败或不开放该档，不增加套餐查询服务。

界面采用固定官方 standalone ModelSelector／ModelSelectorEffort，关闭搜索，外观及交互见 [UI 约定](../../ui/DESIGN.md#2026-11-11-chatgpt-模型设置)。打开页面、原账号变更通知及手动重试时读取目录，不轮询。同一 ChatGPT 来源内选择模型、深度、速度或恢复默认后自动保存，两角色一次校验和持久化，不再显示「应用并重启」。保存失败保留选择，单次重读目录并提供「重试保存」；模型失效、登录未确认、磁盘写入失败及保存结果未知分别提示，不把保存失败当作登录失败。已保存配置失效时要求用户处理；切换模型保留兼容参数，其余采用目录默认深度和标准速度并说明；无可调深度时使用目录声明的默认值。

`applyCodex(roles)` 沿真实 preload、Electron、runtime、dev-host 的现有账号管道传递完整参数；同来源使用 `apply-models`，不发停止请求。服务重新读取目录及权限，校验完整组合后用既有 profile 写入器原子保存，再同步替换内存角色覆盖；失败保留原文件和内存。写入器先取得既有 `.pending` 排他文件，再读取合并，防止与主进程快捷键保存互相覆盖。可信桌面入口单独传递实际 `desktopProfile` 路径，兼容 `appData` 仍指向旧资料的采用场景。无参数调用仍保留来源切换合同，不向网页开放账号写入。

各引擎在下一轮开始时读取同一份角色配置，用现有 `thread/settings/update` 确认后更新本轮快照，逐轮显式传模型、深度和服务档；当前运行或准备中的轮次保持原参数。图片能力沿现有缓存按模型判定，标准档显式发送 `serviceTier: null`，不继承旧 Fast／Ultrafast。正常切换沿用原线程和进程，不重建会话、runtime 或 CODEX_HOME。原生更新失败时不推进快照；服务仍按原故障合同关闭并恢复不确定的引擎，后续请求重新加载已保存配置，不承诺故障后的进程不变。跨来源仍由「应用并重启」进入原确认、安全停止、原子保存及重启流程；取消、确认失效、停止未确认或保存失败均保全原配置。

2026-11-12 修复已补充真实 preload 源码与已注册主进程处理器的组合回归，以及 runtime 完整参数、实际 profile 写入失败和活跃轮次隔离回归。固定 Codex 0.163.0 的隔离模型替身验证同一原生线程内模型、深度及三档速度切换和标准清除；实际设置组件复验自动保存及窄屏。复验命令与结果见[测试说明](../testing.md#chatgpt-模型设置)。本次未安装或发布，真实 Pro $500 资格与调用、打包后的平台验收仍待单独安排。

## ChatGPT 恢复会话的模型传输

2026-11-13 源码实现，尚未安装或发布。新 ChatGPT 会话继续走 Codex 原生连接；恢复的 Main／Worker 会话继续经过现有历史桥，现在同时支持 WebSocket 与 HTTP/SSE。网站模型来源仍遵守原有 HTTP 合同。`nativeHistoryBridge(proxy, dispatcher?)` 及 `{baseUrl, close}` 接口不变，无新配置、数据库或会话缓存。

桥仅监听回环，只接受原有认证及来源边界。WS 上游固定为 ChatGPT Codex 的 Responses 地址；真实上游 101 成功后才接受下游升级。两跳握手由 `ws` 分别校验生成，保留端到端会话头和实际子协议。只将 `response.create.input` 交给现有 `nativeHistoryInput()`；预热、增量、工具及原生加密推理保留，原 rollout 不改写。`createWebSocketStream()` 保持文本消息边界并提供背压；请求与消息上限为 64 MiB，压缩继续关闭。

HTTP／HTTPS 代理使用直接依赖 `https-proxy-agent@7.0.6`，SOCKS 使用 `socks-proxy-agent@8.0.4`，保留代理优先级、远端 DNS、代理认证及 NO_PROXY。HTTP 仍复用 Undici。代理失败不直连；握手 15 秒截止返回 504，网络失败返回 502，上游拒绝状态及正文原样返回。426、服务错误、断线和重试均由固定 Codex 原生处理，不将所有失败转换为 HTTP 降级。桥不重发模型请求或工具动作。关闭、取消及拒绝后的半开 socket 均回收；已接受的边界是尚未完成的 SOCKS 协商由库按最多 30 秒释放，取消后不发送模型消息。

实现参考 [Cindy 的握手与错误语义](https://github.com/makecindy/cindy/blob/19184428ffbb6ec25d143050af4568a85deae68c/packages/anthropic-compat-proxy/src/server.ts) 与[完整消息转换边界](https://github.com/makecindy/cindy/blob/6afea2c125a2a087a432bcd6d226e2a776586875/packages/anthropic-compat-proxy/src/websocket-message-transform.ts)，使用已有 ws 处理帧和分片。没有移植其路由注册、握手缓存、回探或附件外置体系。

### 实模性能记录

使用独立 HOME、runtime 和工作目录，读取用户允许的现有测试授权后只在私有测试目录临时使用。模型固定为 `gpt-6.1-terra / high / 标准档`；每个完整样本包含三个 turn 和一次合成常量工具调用，共四次有输出响应。WS 另有一次零输出预热。上传量包括预热，按应用层 JSON 计，不含 TLS/TCP/WS 帧开销。三轮耗时为 turn/start 到 turn/completed 的累加，不含启动引擎、目录读取和历史注入。

首次候选完整执行八个样本；中等上下文第一对的初始系统输入相差约 4,815 token，排除该对的耗时比较。后续驱动关闭项目文档自动注入、先读取模型目录，并校验初始输入 token 的差值不超过 64（允许临时路径等元数据差异），避免将不等上下文当作提速证据。

首次候选约 37.3 万 token 组四个样本均完成，三轮上传约从 7.35 MB 降至 1.84 MB，减少约 75%；首次实际任务请求后，WS 后续请求约 2 KB。逻辑 input usage 仍约 37 万 token。耗时有明显波动：该批 HTTP 平均 35.77 秒、WS 平均 27.75 秒，仅为两个样本的观察，不能承诺固定提速比例。

关闭修复后的补测两次收到 `server_is_overloaded`。第一轮旧驱动约 5 秒收到错误后仍等到 180 秒，被主动停止；最终驱动匹配生产有限重试设置，收到模型错误立即结束整个专项，避免继续付费样本。最终第三批在第 3 个样本停止，**完整实网性能专项未通过**；不能用较早成功样本覆盖该结果。以下保留全部成功、失败和中止记录。本机存在日常任务及并行回归负载，时延不是受控的协议性能归因。
