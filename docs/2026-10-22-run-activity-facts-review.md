## 发现与修复

| 级别 | 问题 | 修正与保护 |
| --- | --- | --- |
| P2 | `history.process` 展开时为全部工具解析导航；成果 owner 因而逐条读取并校验文件，已打开的阅读区还会随无关流式 node revision 反复读取 | 复用原 endpoint 的可选 `itemId`，展开只读事实，点击才解析准确所选条目的导航。HTTP 保持既有409错误合同并校验 ID；owner 在准确线程/过程内查找条目，原文件授权/hash 校验不变。阅读区不因其他调用或公开文字的 node revision 重读。没有新增缓存、轮询或读取接口 |
| P2 | prepared/submitting 的已授权文件可能带出尚不存在的原答复按钮；关联消息也未验证属于准确当前线程 | 成果仍沿 publication owner；原答复必须有 recorded 回执，并确实存在于该线程的 assistant 消息中。缺失、跨线程、撤销不产生入口，不把 prepared 当作交付成功 |
| P2 | 从活动进入任务面板，返回总览再选另一任务，会残留原活动的版本说明 | 离开关联目标时清除说明，呈现也检查准确 rootTaskId；重新打开时同步清除已取消的历史请求引用，避免旧请求阻塞新读取 |

前两项先增加隔离行为断言并确认失败，修正后转绿。新增覆盖：默认展开0次导航解析、选择1次、无效/越界条目、prepared无原答复、recorded但消息缺失、跨线程、准确消息、撤销；真实浏览器补查流式更新后读取次数不变，以及返回总览切换任务后不残留旧版本。

其余审查结论：原调用 ID/revision 和记录顺序保持；读取、验收和正式交付不互相推断；公开事实采集异常仍不能改变业务回执；MainProgress 渠道数据未扩展；历史通用记录不补写，Worker 事件卡不改成操作入口。官方 Run Activity DOM/CSS、列表、字体和间距未改动。任务生命周期、停止/返工、队列、审批和正式成果归属未改动。本批没有剩余已知 P1/P2 审查发现。
