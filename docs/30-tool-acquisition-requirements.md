# 工具获取、使用与自主扩展

更新：2026-11-08。当前策略为**预装工具管理、反馈与归档复核三个 Homer Skill，具体工具按任务需要主动获取**；不要求首启补齐浏览器、电脑或办公组件。当前实现以 [homer-tool-management](../.codex/skills/homer-tool-management/SKILL.md) 简短入口和八份按需参考组织两类清单：精选列具体工具、功能、来源链接及安装方法，认可市场／集合列发现入口；安装与创建配方仅作为操作参考，自建条件在入口简短说明，复用固定 Codex 0.163.0 的发现、加载、配置、安装及审批。本文取代早期独立预装器、全量随包、签名目录服务和安装状态库方案；不把这些旧建议列为本轮前置条件。运行采用证据见文末。

## 目标与完成标准

用户交办任务后，Homer 先使用已有合用能力；不足时发现具体来源、检查详情和必要授权、安装配置、实际调用、核验成果并交付。后续任务、重启和应用更新继续复用原生事实。用户无需预先知道工具名称。

“长期具备”指常规产品能力，不保证任意服务、平台或账号都可用，不在后台无限搜索或重试。安装、连接、当前会话采用、实际调用、成果交付分别判断；一个回执不代替其他证据。Skill 可以包含执行脚本，Markdown 格式不等于无执行风险。

所有类别统一采用：**原生可用即用；确认原生存在具体缺口后选可独立集成的成熟工具；最后才制作最小方法。** 不建立人工功能白名单，不将所有工具强制包装成 MCP／Plugin，不建设第二安装引擎、客户端、配置数据库或 Worker 版本代理。

## 预装与按需获取

- 标准新实例预装 `homer-tool-management`、`homer-feedback` 与 `homer-archive-review` 的完整目录，保留 Codex 原生能力和已有用户工具。
- 首次启动使用现有账号引导与欢迎页。收到真实任务后，按具体缺口获取工具。
- 真实任务需要工具时依照两类清单完成安装、配置、验证和同请求续接；不止给安装步骤，也不要求用户重启。已有授权不重复问，必要的具体审批照常。
- 浏览器按需首选 Playwright；电脑操作选择独立可用的成熟 CUA 执行器。基础本地控制不以 OpenAI Apps 认证为前提；云端 Browser Use 保留为用户可选来源，不擅自卸载。
- 文件、命令、下载和审批仍需宿主实际提供。当前 Shell 整轮联网隔离不因 Skill 改写而解除；阻塞需准确报告并独立修复接线，不借安装工具绕过管理面保护。

## 复用原则与两类清单

入口只保留精选工具与认可市场两类清单，不单列已有本地能力、用户来源或自建层级。

| 顺序 | 实际入口与方法 | 缺项及处理 |
| --- | --- | --- |
| 1 精选 Skill 与工具 | [按用户任务分类的工具与安装表](../.codex/skills/homer-tool-management/references/curated-tools.md) | 参考 Cindy 实际公开目录；自动化、设计、开发、沟通、集成与办公均提供独立上游和安装方法。原生已有能力不重复列作待安装；OpenAI 云服务另作可选附录 |
| 2 认可的市场与工具库 | [市场、集合及查找方法](../.codex/skills/homer-tool-management/references/trusted-sources.md) | skills.sh、MCP Registry、Smithery、Docker MCP Catalog、Homebrew、npm、PyPI；另列发布者 Skill 集合，不重复维护具体工具安装表 |

来源未配置或候选不适配时透明继续；目录超时／认证失败标为“未完成检查”，可沿原授权检查其他来源。本人拒绝、禁用、账号资格与权限限制不能经镜像、别名或自建路径绕过。已有合用工具无需换装。

精选候选直接列名称、功能、形式、准确包名／仓库子目录、来源链接、安装命令、条件和最小验证；认可市场／集合则列发现入口、覆盖范围和取得安装信息的方法。已有具体工具统一进入精选，来源认可不等于其中每个工具已验收。安装／配置／授权状态以原生事实和既有 Homer 业务回执为准；不复制一份权威安装状态。当前不要求签名市场、远程可信服务、独立预算系统或自动整套预装。

自建只保留简短规则：没有合适的现成工具或用户明确要求时，优先 Skill／脚本／CLI，确需标准工具接口或组合分发时才做 MCP／Plugin；复用原生 Creator、运行时和成熟 SDK，实际验证、采用后继续任务，长期可复用的方法保存或更新为 Skill。不因暂时断网、账号或权限缺口重造服务。详细命令是操作参考，不单列第三、第四层。

主 Agent 和 Worker 使用当前原生已发现、适用且获授权的能力；Worker 不竞争修改共享配置或自批安装。Homer 保持唯一业务管理者，原生 multi_agent 继续暂缓。审批、现有网络边界、读写范围、队列、publication、停止和自动更新保护不因 Skill 放宽。

## 浏览器、电脑与办公

- 浏览器／电脑优先原生实际可调用工具及正式配套组件。固定 0.163.0 尚未找到 bundled Browser／Computer Use 允许第三方独立宿主对接和再分发的公开合同；这是未找到公开支持，不是断言永久不支持。官方 [Browser](https://learn.chatgpt.com/docs/browser) 描述桌面能力并明确非 CLI／IDE 路径；[Computer Use](https://learn.chatgpt.com/docs/computer-use) 描述桌面插件与本人系统权限。不能凭 flags 或桌面说明认定 Homer 可调用，也不复制专有资源。
- 有该缺口时可按需选公开支持独立集成的 Playwright CLI＋Skill、Playwright MCP 或 Cua Driver。它们只是候选，非当前已安装保证；版本、依赖、平台、许可、Homer 宿主权限和最小调用分别核验。云端 Browser Use、原生 bundled Browser、独立 Computer Use API 不是同一种产品；认证、费用和数据去向不同。
- Office 见 [办公参考](../.codex/skills/homer-tool-management/references/office-tools.md)：Word／PPT／Excel 可编辑结构、PDF 页面、视觉渲染和公式计算分别检查。`openpyxl` 不计算公式，读取缓存不证明本次重算；缺渲染器时明确未完成视觉检查，不把文件存在当成品验证。交付目标文件及实际下载入口，不用 PDF 预览替代可编辑文件。
- 来源和许可会变化。2026-10-18 核验 [OpenAI Skills](https://github.com/openai/skills) 已标 deprecated，转向 [OpenAI Plugins](https://github.com/openai/plugins)；仍可读的旧 PDF Skill 仅作兼容来源。当前固定版本 `.system` 仍按实际发现使用，不为追逐上游改写它。

这些方法不声称全部浏览器、桌面或办公工具已在 Homer 实测；真实工具闭环证据单列于 [原生生命周期验收](31-native-tool-lifecycle-validation.md)。

## 任务执行、失败与更新

1. 明确成果与现有授权，按任务需要读取精选或认可市场清单。
2. 选择确定来源、子目录、版本、依赖及目标目录；具体安装格式按需读取操作参考。
3. 仅对必要新增操作请求具体确认：新程序、连接、账号、系统权限、费用和外发。已有效授权不重复询问；可信来源不隐含永久全权。
4. 沿原生接口或现有成熟工具完成配置，查询原生事实，最小调用并核验用户成果；真实服务与合成证据分开。
5. 中断后不执行后续步骤；未知回执先查事实，不盲目重放安装、发布或外发。已安装合用则跳过；被拒／禁用不恢复。失败只沿现有任务通道记录必要对象、原因和待办，不存秘密或另建状态库。
6. 更新前比较完整源／目标清单和 hash，保留用户修改与备份；失败保留旧版。回退只处理本次拥有、且未被后来修改的文件，不回滚已产生业务事实。移除不误删共享依赖与用户成果；当前入口移除不等于自动清理整目录。
7. 原生重扫后证明当前主对话实际采用；纯 Skill 不强行重启引擎或新建主对话。重启／应用更新后重新核状态，不从旧文字推断在线。

交互复用主对话、现有待答卡、草稿和停止语义，遵循 [DESIGN](../ui/DESIGN.md)，不增加常驻内部工具流水。工具补装失败不阻塞正常聊天，后续适用任务再续接，不后台无限修复。

## 必须区分的缺陷与限制

| 风险 | 处理及代价 |
| --- | --- |
| 来源级别误当安全或执行授权 | 每个对象、版本和权限核对；目录仅提供来源 |
| 目录失败导致等待或造轮子 | 标明未完成检查，有界转向已有来源；不称查无结果或绕拒绝 |
| 发现 Skill 却缺执行器／权限 | 在实际宿主核依赖，最小调用；桌面可能需要产品接线，不能靠提示词解决 |
| 文件或网页提示注入、越界包 | 检查路径、链接、内容、依赖；现有宿主审批和隔离继续负责，静态检查不等于无恶意 |
| 更新覆盖用户修改或不完整目录 | 完整清单、hash、冲突审阅、备份和精确回退；不只替换入口 |
| 原生接口／上游仓库变化 | 固定版本实证与维护日期；失效时准确报告，不造第二引擎兜底 |
| 安装回退误当业务撤销 | 第三方写入、外发与文件成果分别判断；新事实后不能套旧业务快照 |
| 对全生态承诺过度 | 仅交付实际观察，明确缺账号、费用、权限、平台或外部地址；每种工具按任务验收 |

## 独立待办与未配置项

### 自动采用补充契约与差距（2026-10-18 16:54 历史基线）

新增产品要求：新装／更新 Skill、MCP 和工具不要求用户手动重启 Homer，也不要求再发一次原任务。优先原生热刷新；当前模型轮无法采用时，宿主在安全边界自动续接同一用户任务和 thread，必要时仅重连子引擎。保留在飞工具、Worker、审批归属及 unknown 不重放边界，不能以完成一次安装扩大授权。以下表格记录实施前的 RED 基线；后续实现与运行状态见下方“原任务自动续接交付”。

| 范围 | 实证与限制 |
| --- | --- |
| 原生 Skill | 固定 0.163.0、空 HOME、无凭据无模型夹具：新增和修改后 `skills/list(forceReload)` 在同一已加载 thread 发现更新；Homer 真实 CodexEngine 的非强制刷新也保持同一子进程／thread |
