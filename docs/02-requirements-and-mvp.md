# 需求与首版范围

## 1. 范围状态

已确认首版使用命令行对话测试，不建设图形界面；后续优先接入现有 IM，不自建各平台 App。M0 范围已批准实施；其他 P0/P1/P2 划分仍为后续演进建议。

- M0：当前首先实施的最简闭环，详见第 9 节。
- P0：M0 通过后的基础能力扩展；下列 R01–R08 的完整要求不再全部阻塞 M0。
- P1：通过首个 IM 适配扩展到真实日常使用与手机协作。
- P2：扩大无人值守、自主能力获取和商业化规模。

## 3. P0 用户路径

1. 用户通过命令行发送自然语言消息；主 Agent 先确认必要目标与材料。
2. 简单回答直接处理；复杂工作建立事项，派发独立执行并返回进度。
3. 用户继续发送新工作，或通过事项名称、必要的短标识补充要求，无需打开事项页面。
4. 需要确认时显示事项、具体动作、影响和选项。
5. 返回成果，说明完成范围、核验结果和剩余问题。
6. 用户继续修改时沿用原事项，不无故创建重复事项。

用户可以自然语言询问「还有哪些事没完成」，系统返回简短文本清单；不要求用户手动维护任务表或记忆一套管理命令。

## 4. 变更与控制要求

- 明确事项上下文的补充直接送入对应执行；主对话中的模糊指代先澄清。
- 变更被保存／排队不等于执行者已经采用；涉及当前结果时需可确认的应用状态。
- 请求取消不等于已经停止；确认停止前不显示为已取消。
- 取消阻止尚未开始的后续操作，不能承诺撤销已发送消息或其他不可逆动作。
- 失败保留原因和成果；重试建立新的执行尝试，不覆盖此前事实。

## 5. 工具范围

P0 固定预装少量工具，候选通过实际任务筛选，不预先承诺具体供应商。

文档首版建议先选两种真实可验收格式（如 DOCX 和 XLSX）；PPTX、复杂既有文档格式保留、宏与修订等单独评估。PDF 可作为预览或交付扩展，不代替可编辑文件要求。

工具接入优先级：官方 API／成熟结构化工具 → 浏览器自动化 → 必要时桌面操作。按效果选择，不能为使用 CUA 而放弃更可靠的接口。

## 6. 授权原则

高自主性通过用户事先授予的范围实现。系统策略决定实际可执行范围，模型生成的指令不能自行扩大权限。

登录凭据、MCP Token 不写进普通聊天、技能正文或日志。用户确认必须绑定动作，不能将一次批准无限扩展。

## 7. 首版排除项

P0 不建设图形界面或自有 App，不要求接入 IM、公开注册付费、开放任意插件安装、手机接管、本机锁屏后的 GUI 操作或生产级多用户云服务。公开试用前必须补齐对应账号、隔离与运营要求。

## 8. 对话与渠道要求

- CLI 是测试入口，支持指定会话继续发送消息；自然语言正文通过参数、交互输入或标准输入提交的具体形式，在实现时确定。
- 事项更新、确认请求与成果均通过消息表达，不以按钮、事项页面或专有 UI 组件为必要条件。
- 后台事件返回时标明事项名称；多项确认待处理时不把裸「同意」随意匹配到任意请求。
- P0 成果交付给出真实本地路径与内容摘要。未来 IM 由渠道适配器上传文件或提供受控下载方式，不能直接把本机路径当作手机可访问链接。
- 后续 IM 先选择一个平台验证，再增加其他平台；不能将各平台线程、附件、消息长度和编辑能力视为一致。

## 9. M0：当前最小实施范围（已批准）

### 9.1 唯一目标

证明主 Agent 可以通过真实 Codex App Server 会话，将用户委托派给独立执行会话，保存状态、产出实际文件，再向用户交付并继续处理修订。

先验证机制，不验证行业需求。采用本机单用户、固定模型作为实施假设；CLI 仅供开发与对话测试，不代表最终用户必须使用命令行。

### 9.2 必要功能

| 编号 | M0 必须实现 | 最小边界 |
| --- | --- | --- |
| M01 | CLI 多轮对话 | 一个主会话，输入自然语言，输出进度、结果与错误 |
| M02 | 主 Agent 通过工具创建并派发事项 | 简单问答不派任务；文件工作真正进入独立 Codex 会话 |
| M03 | 多个独立执行任务 | 主 Agent 决定派发数量与时机；不设固定单 Worker 或每消息一次派发限制，执行期间可查询状态 |
| M04 | 最小持久记录 | 保存事项、执行、引擎关联及结果；修订沿用事项、新建执行尝试 |
| M05 | 读测试材料并写 Markdown | 仅操作显式准备的测试工作区，不接浏览器、Office 或外部账号 |
| M06 | 成果核验与回传 | 路径存在、为授权输出范围内文件、非空；结合需求核验内容，返回路径与摘要 |
| M07 | 失败、停止与重启如实报告 | 无无限重试；停止请求与确认分开；重启标记未确认运行的任务为 interrupted，不自动重放 |
| M08 | 最小执行边界 | 限定文件范围与运行超时；非许可动作拒绝并说明，不自动批准所有操作 |
| M09 | Worker 授权与业务提问先交主 Agent | 依据真实授权、目标和上下文自主批准／拒绝／回答；仅超范围或不明时升级用户，原进程继续；持久记录、并发准确路由与失效对账 |

### 9.3 不纳入 M0

任意子 Agent 递归分工、运行中修改执行指令、跨进程交互审批恢复、独立客户端断线续跑、自动精确续跑、模型路由、精确金额硬限额、长期偏好学习、语音、IM、账号付费、浏览器、桌面操作、Office、自主安装、定时自动化。

M0 使用单个常驻 CLI 应用进程，程序内异步管理主 Agent 和执行会话，不预先建设 daemon、HTTP 服务或消息队列基础设施。关闭整个 CLI 即结束当前运行环境；正常退出尝试停止任务，异常退出由下次启动对账。不能承诺关终端后继续工作。

Worker 授权／提问现先交主 Agent，明确拒绝和业务答案均返回原 Worker；超出范围或无法判断才询问用户，等待期间保留进程且主会话继续接待。默认自主范围可覆盖获准任务内项目修改、测试与普通依赖安装的判断，但不增加实际工具能力。本期仍限制为 Markdown 工作流；原生桥接的批准校验只接受本 Run 读取子集。真实原生权限工具在当前环境未提供，fixture 与实测分开报告，详见验证记录。普通最终文本提问不自动识别。尚未完成的真实高风险操作不作为验收材料。

### 9.4 固定验收材料

使用不含敏感信息的会议笔记，提出「整理成行动清单，写入 Markdown，保留未明确负责人或时间的待确认项」。完成后要求「按负责人分组，未确认的单独列出」。输入副本留在专用测试工作区，维护中的需求文档不作为可写实验材料。

不以固定关键词或预写结果冒充 Agent；事项派发与文档内容必须来自真实执行。自动化单元测试允许使用模拟引擎，但不能代替端到端验收。
