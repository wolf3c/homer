# 使用荷马

[English](using-homer.en.md) | **简体中文**

从一个明确的目标开始，让荷马协调助手、审核成果，再根据你的反馈继续修改。产品介绍见 [README](../../README.zh-CN.md)。

## 安装与启动

桌面安装包正在准备，当前没有已验证的公开下载链接。安装包发布并通过下载、安装和启动验证后，再补充对应平台、CPU 架构与安装步骤。不要把源码压缩包当作桌面安装包。

现在愿意自行配置环境的开发者，可按[源码运行指南](getting-started.md)构建并使用 CLI 或本地 Web。该路径仍是开发预览，不代表桌面版安装体验已完成验收。

## 开始前确认

- **模型连接：**必须有可用且获授权的模型服务。安装客户端不等于已配置好模型；荷马按量服务、ChatGPT 套餐接入的可用性和资格以实际发布信息为准。
- **费用：**客户端计划免费，模型调用另计。一个任务可能包含多个助手、重试和修订，没有固定的单任务费用或经过验证的全局费用硬上限。
- **材料与权限：**首次使用公开或虚构材料。根据实际任务确认允许访问的文件、工具和账户，不把客户资料直接用于试跑。

详细规则见[费用与数据](data-and-costs.md)。

## 第一个任务

先完成一个无需额外素材下载的方案任务。以下材料全部虚构，可直接复制到荷马对话中：

```text
请根据这份简报，组织助手完成一个产品出海页面的发布方案，并审核后交付。

简报：我们是两人小团队，为自由职业者提供项目交接工具。
已确定的功能只有任务清单、文件附件、审核批注。
目标是在两周内准备好英文产品介绍页。
目标国家、定价、预算和两个人的具体分工尚未确定。
本次只整理方案，不执行采购或对外发布。

请交付三个 Markdown 文件：
1. requirements.md：已知需求、范围和验收标准。
2. questions.md：信息缺口，以及需要我决定的问题。
3. plan.md：按相对天数组织的两周计划、依赖和风险。

未提供的信息标为“待确认”，不要编造市场数据或客户反馈。
如有必须先回答的问题，请先问我。完成后说明每份文件的位置和要点。
```

这是用于上手的示例请求，不是已完成真实模型验收的案例，不承诺固定耗时或费用。

## 回答问题、检查成果、继续修改

荷马询问关键信息时，在同一对话中补充。CLI 使用者需保持交互会话打开，便于当场回答。

收到成果后打开实际交付文件，逐项检查：

- 三份文件是否存在、可打开且有内容。
- 需求是否忠于简报，未知信息是否明确标为待确认。
- 计划是否说明依赖、先后顺序及需要你决定的事项。
- 是否出现简报未支持的承诺、市场数据或用户反馈。

然后在同一对话中提出一次具体修改，例如：

```text
先只面向英语使用者。请把计划改成一人负责文案、一人负责页面制作，
第一周完成初稿，第二周检查和修订。其他未知项仍保留待确认。
请检查三份文件是否一致，并交付修订后的文件。
```

可在支持的预览界面中批注具体位置，也可直接说清文件名、段落和预期修改。以实际交付文件验收，不只看聊天中的完成说明。真实项目对外使用前，由你确认内容与权限。

## 遇到问题

| 现象 | 处理方式 |
| --- | --- |
| 找不到安装包 | 当前仍在准备；不要使用来源不明的安装包。开发者可查看源码运行指南。 |
| 模型连接或认证失败 | 检查当前运行配置、服务资格及余额；源码方式须确认认证所在的专用 Codex Home 或密钥环境变量。不要复制其他应用的认证文件。 |
| 附件无法读取 | 先使用纯文本完成示例，再按源码指南准备相应文档或媒体工具。上传成功不代表内容已被正确读取。 |
| 任务等待输入 | 在同一会话查看问题并补答，不反复重复发送同一任务。 |
| 没收到文件或文件不完整 | 明确指出缺失文件、实际观察和验收要求，请荷马补齐；不要自行将任务判为已完成。 |
| 需要结束 CLI 会话 | 输入 `/quit`。退出会停止执行；需要补答时保持交互会话打开。 |

仍无法解决时，通过 [GitHub Issues](https://github.com/wolf3c/homer/issues/new?template=bug_report.yml)提供版本／提交、系统与 CPU 类型、运行方式、虚构输入的复现步骤、预期与实际表现、错误码。公开反馈不要附密钥、认证文件、客户资料、完整日志或原始会话。安全或私密信息不放在公开 Issue 中。
