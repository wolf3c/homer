## 使用方式与职责

新 Homer 数据实例第一次连接可用且主 Agent 空闲时，宿主沿 `submitMessage` 提交一次用户角色消息：

> 首次启动自动发起：请使用 $homer-initialize 完成首次初始化，按需调用工具管理 Skill。

消息在现有对话中显示，前缀明确来源；沿正常持久主队列、generation、原生审批、停止和安装后自动刷新／同线程续接。不用内部事件伪造用户授权，不改现有审批保护。这条请求允许确认方法就绪，并在存在实际任务时按现有规则处理必要工具，不等于批准任意程序、登录、系统权限、费用或外发。

`homer-initialize` 只确认 [homer-tool-management](../.codex/skills/homer-tool-management/SKILL.md) 能被发现、入口和参考可读取，并简短介绍“需要时主动获取工具”。没有真实任务时不逐类核浏览器／电脑／办公依赖，不扫描市场、不安装具体工具或发起付费测试；“初始化完成”只代表方法就绪。用户已有任务时先工作，当前已提供工具直接使用，不要求重复盘点本地能力；由管理 Skill 只检查并补齐该任务的确切缺口，再自动采用并续接。来源与安装规则只在管理 Skill 维护，精选远程目录／认可第三方清单未配置时透明跳过，不无界搜索。

用户有真实任务优先处理。中断、拒绝、未知或失败不记为完成，也不在每次打开时重试；用户说“继续初始化”时按普通消息重新核原生事实，不重装、不覆盖用户选择。无初始化调度器、能力进度系统、安装事实库、版本差量重跑或新的 UI。

## 首次范围与防重复

“首次”针对 Homer 专属数据实例，不按页面、应用版本或账号计数。仅本功能启用后新建主对话、且 runtime 与原生 HOME 分别是应用数据根下 `runtime/`、`codex/` 的标准实例有自动请求资格。自定义 runtime／共享 HOME 不自动发起，仍可由本人普通消息初始化。已有实例升级保持现状，可由用户明确发“继续初始化”；当前开发日常不因升级自动启动整套补装。复用现有 runtime／HOME 归属校验，不支持另一个 runtime 绕过归属保护共享同一自动请求。

宿主只保留一个稳定首启 requestId，随新主对话在既有事务中保存；该 ID 的现有用户输入／receipt 是“已提交”依据。模型未连接时等待既有连接完成或后续正常工作边界，不轮询模型。先检查已登录／配置连接条件与两个 Skill 的原生发现（不额外调用模型探测网络或额度），再以固定 ID 原子提交；用户先发消息则先服务用户。重开、服务重启或提交后崩溃均不创建第二条，处理中的未知仍按主队列现有 reconcile 保护，不重放安装。

requestId／receipt 只证明请求提交，不证明工具安装完成。Skill 不读写业务 DB；失败之后靠普通对话和原生状态续接，无额外完成字段或恢复任务。安装是否落地、当前是否采用、实际调用是否通过分别核对。

## 发行与采用

两个 Skill 必须按完整目录随发行候选携带，发布到 Homer 实际专属 HOME 的原生 `skills/` 发现路径。初始化 Skill 仅需一个 `SKILL.md`；工具管理 Skill 保留现有九文件目录及相对引用。原生 creator／installer 从实际发现路径读取，`.system` 不修改。

发行文件不覆盖已有用户修改、禁用或卸载选择。分发缺口只补最小接线，不引入另一套安装 API；原生发现、读取及主轮显式绑定均须核验。现有管理流程负责刷新，必要时安全重连后台子引擎并恢复原 thread，不能要求用户手动重启或新建对话绕过问题。

## 完成检查与交付边界

- 没有实际任务时只检查管理 Skill 及参考可读，不安装 Playwright／CUA／Office，不声称工具已就绪；有任务只补必要缺口。
- 首次冷启动只提交一次；页面重开、服务重启、原子提交前／后异常和处理中崩溃不重复。
- 未认证无模型循环；连接完成后正常边界提交；已有用户输入优先。
- 自动消息为用户 role，保留清楚前缀；审批、拒绝、停止、新消息和原任务自动续接沿现有路径。
- 失败只产生普通请求结果，不写初始化完成；“继续初始化”是新普通请求，先核实际状态。
- 隔离固定 Codex 无凭据、无真实 thread 验证两个 Skill 完整发现／读取；结构校验和场景审查覆盖触发、引用、未知、缺依赖和本人动作边界。
- 不改 UI；如合入时新增 UI，另验 605px 与桌面渲染和交互。
