## 执行与隔离

- Node 22.22.0、Codex 原生引擎 0.163.0；Main 使用 GPT-6.1 Terra、medium、默认服务档位，取自现有 Homer 的模型选择。
- 每个场景新建 runtime、`CODEX_HOME` 和 Main 会话。业务树放在仓库外的合成用户主目录中，避免继承真实仓库的 Git 根和 `AGENTS.md`。Homer 的既有目录事实依赖传入这个合成 home；Worker 根准备、MCP、派工受理和原生初始化均运行真实代码。
- 经本轮付费调用授权，读取现有 ChatGPT 登录的短期 access token，以原生 `chatgptAuthTokens` 外部认证登录独立进程。未复制 refresh token、会话历史或日常数据库，未执行登录刷新；共用登录额度，不代表独立计费账号。
- 原生工具配置拒绝真实用户主目录，合成业务树只读，系统程序目录只读；工具网络、Web、Apps、Plugins 与记忆生成关闭。仅设置合成测试所需的系统 PATH。调用前用本地响应确认：可读合成文件，真实用户目录内的合成探针不可读，合成工作目录不可写。
- 只有 Main 使用真实模型。Worker 仍启动真实 Codex 引擎、采用实际 cwd 并加载原生规则，但模型上游连接到本地合成 Responses，保持请求等待直到 Main 本轮完成，避免 Worker 完成事件触发额外付费 Main 轮次。这不验证 Worker 的实际解题质量。
- 六轮结束后均确认宿主与原生进程停止。日常认证文件和 desktop profile 的前后 SHA-256 相同，真实用户主目录兜底标记的存在状态未变；无日常 runtime 写入。

## 计量口径与修正

首次派工耗时从 `Homer.message()` 提交本轮任务开始，至真实 `worker_open` 处理完成并取得有效 Worker 回执；使用单调时钟。宿主／Main 冷启动单列在 JSON 的 `bootMs`，不混入派工耗时。token 覆盖 Main 整个业务轮，包括派工后的确认／读取；不等于派工之前单独消耗的 token。

token 使用引擎 `usage.total` 的白名单计数，六例均逐字段与对应 Main 原生历史的最终 `token_count` 核对一致。缓存输入包含在输入内，推理输出包含在输出内，不能再次相加。

工具轮次按原生 `token_usage_record` 边界分组：一个模型响应中有工具调用即计一次，同轮并行调用不重复计轮次；另列实际目录查询、文件工具和业务工具次数。单纯搜索原生工具目录的 code-mode 调用也占一次工具轮次。

初次临时探针有两项计量问题，已通过原生记录与无费用本地回放纠正，没有为修正指标重复调用付费模型：

1. 直接数 `response.completed`，每例比 Main usage 响应多一次。这些额外原生响应不属于 Main 工具轮次。本地新 profile 回放另见一个 `gpt-5.6-terra` 标题生成后台请求。正式六例的额外响应 token 未采集到，因此 **324,270 只是 Main 业务轮用量，不能视为账号所有请求的总消耗或货币账单**。
2. Worker 探针最初只检查最后一个本地上游请求，后台请求可能覆盖此前的规则判断。最终改以各真实 Worker 原生历史中的 cwd 与合成规则标识核对；独立本地回放也确认目标规则存在于实际任务请求的 `input`。两个浅目录样本确实只加载父层规则，没有被计量修正掩盖。

## 后续判断与边界

保留按需查询的简单机制。下一步最小改进方向是明确“项目根只是入口；任务涉及有独立规则的子模块时，定向确认子层位置并选择能加载所需规则的 cwd”，同时避免不必要的分支查看。应先针对 U1、U2 做提示词／工具说明对照，再决定是否扩大样本；本轮没有实施这些改动。

未覆盖旧 Main 真实模型恢复、跨项目任务、目录失败／澄清停止、Windows、真实 Worker 解题或日常安装。原生与离线已有验收结果仍分别保留；本轮不替代这些门槛。临时认证、原生历史、数据库与源码快照在确认停止后清理，只保留本报告和不含凭据、原始对话或工具载荷的合成指标。
