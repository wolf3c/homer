## 2. M0 已采用的实施选择

- M0 先在当前 Mac 上本机单用户运行，固定模型；CLI 入口已由 D07 确认。
- 采用 TypeScript + Node.js + SQLite，以实际可用版本为准；只建设单进程 CLI 和最小执行队列。
- 主 Agent 派发独立 Worker，先处理指定会议样例并生成 Markdown，完成后修订；后续按用户要求已开放多 Worker。
- 先不接浏览器、Office、IM 或自主安装；现已加入原进程的 Worker 授权／提问闭环，能力边界见技术方案；不建设独立常驻服务。
- 原先两种文档格式、多任务并行等要求移到 M0 之后；不提前建设多引擎或微服务平台。

这些选择按用户批准的 M0 实施。已运行版本、协议及验收证据见 [验证记录](07-m0-validation.md)，不自动扩展为后续产品承诺。

## 并行策略更新（2026-10-16）

用户明确取消固定单 Worker 限制，派发数量和并行选择暂交主 Agent，不先增加复杂 system prompt 策略。程序支持多个独立 Run，同时保持原文件边界、幂等、停止确认、超时与逐一验收；不承诺递归子 Agent、任意工具或运行中修订。


## Worker 自主处理决策（2026-10-16）

用户明确授权：Worker 授权和业务问题先交主 Agent，主 Agent 结合任务目标、已有上下文、实际授权及请求详情自行批准／拒绝／回答，只在超范围或不清楚时升级用户。初始自主范围涵盖当前获准任务需要的项目内文件修改、测试、普通依赖安装；这是产品判断范围，不是对每个“风险”逐个提问，也不是默认批准全部或无限关键词规则。付款、外发、重要资料删除等需要相应授权，示例不取代按目标和上下文判断。

历史方案（本候选已移除该配置及政策资源，见[执行架构候选](34-flexible-execution-candidate.md)）：配置可选 `autonomy` 文本调整主 Agent 初始自主范围，派发时与真实用户消息一起捕获到业务记录；不把模型自己提出的行动视作新增用户授权。该配置不增加宿主工具能力。本期仍是材料读取／Markdown 产物，只增加正式 ask_main 和受限原生读取权限通道，不开放任意命令、网络、Office、浏览器、IM。待答在同进程原 Worker 继续，退出后不能仅靠数据库假装恢复。用户已另行授权的三种任务追加方式由后续任务实现，本次不扩展。
