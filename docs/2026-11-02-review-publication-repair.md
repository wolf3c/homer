## 主 Agent 等待边界与自然收尾修复

本轮仅修改四个产品文件，未改引擎或宿主调度队列，也未新增依赖：

- `src/worker-interaction-mcp.ts`：从 Main 的 MCP 工具列表去掉 `task_wait`，Worker 保留。stdio 与 socket 共用该允许列表，旧缓存发出的调用也不能穿透。

另一个实证原因是：成功验收还会向正在验收的同一协调者发送 `result_accepted`，在交付队列前制造一轮纯确认。仍在 `src/recursive-tasks.ts` 的原验收事务内保留通知及审计，仅将本次新建、接收者就是验收者、`accepted && outcome=succeeded` 的精确回执标为 processed，填写处理者和结果引用。不消费旧回执，partial、failed 或其他接收者的通知保持原行为，不吞掉需要反馈的缺口。

review 核对了工具两条入口、Worker 等待、回执重放、根/子任务、partial/failed 和新增实质问题的保留行为，没有阻塞项。当前这四个产品文件相对本轮开始仅新增 16 行、删除 12 行；相关四个测试文件提供行为保护。没有留下用于强制结束模型或提前伪造 `recorded` 的补丁。

离线验证：最初等待边界/收尾用例复现 6 项失败；成功验收的多余确认又由 5 项用例复现。最终相关套件 129 项全部通过，无取消或跳过，覆盖真实 MCP 协议边界、Worker 合法等待、回执幂等及宿主自然落库；类型检查和 `git diff --check` 通过。合成模型传输只能证明宿主契约，不能单独证明真实模型会选择结束，因此增加了下述唯一一次真实复测。
