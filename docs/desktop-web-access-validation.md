### 本地 Web 访问边界：复现与修复范围

以下为提取独立提交候选之前，共享工作树上的历史复现与验证记录；不代表独立候选的当前检查结果。后续状态见下方“本轮独立提交候选复核”。

2026-11-02，以当时 `src/web-server.ts` 字节为准（SHA-256 `a6a1021f387f64128a423498e094ce9ff6e38953cace16e1c5d02af92dfe03e6`），在独立随机 loopback 端口、纯合成 bridge 上复现：无凭据 `GET /api/state` 返回 200；伪造当前 Origin 后，停止与审批回复请求返回 202、更新确认返回 200，均调用了对应合成处理函数；外站 Origin 和 cross-site 请求仍为 403。证据位于 `.codex/scratch/open-source-web-boundary-20261102/reproduction.json`，不含真实用户数据。该结果仅证明传输入口未认证调用者，不证明真实业务审批一定通过；没有请求日常服务、访问用户数据库或发起模型调用。

现有 `tests/web-connection.test.ts` 4 项本地合成回归均通过；这验证当前免配对及来源限制契约，不是修复后的安全通过结果。根因是 loopback、Host、Origin 和 Fetch Metadata 用于约束监听及浏览器来源，本机程序可自行构造这些请求头。现有业务范围、待答身份和可信更新校验不能代替入口认证。此前明确的免配对决定来自明确的本地开发简化要求，不应在本轮未经确定范围就恢复所有入口的配对链。

建议修复范围：利用现有桌面启动分支，为正式桌面 gateway 与 Electron 主进程增加生命周期一致的随机访问凭据，自动绑定正式界面的请求；不要求用户复制密钥、找连接文件或手工配对。凭据不进入 URL、命令行、日志、WebState、模型上下文或持久业务数据，不能注入预览 frame、其他窗口或外站；所有敏感 API 和流式连接须先检查，再调用 bridge。桌面启动缺少有效认证信息应明确失败，不能退回无认证入口。旧已运行 gateway 不自动切换，开发浏览器免配对仅继续用于可信的本机开发，不作为普通用户的独立分发入口。

实际修改 `src/web-server.ts`、`scripts/dev.mjs`、`packaging/electron/main.mjs`、相关 HTTP／桌面隔离测试及运行说明；沿现有私有进程通道传递，不新增认证服务、账号、数据库或手工配对页面。移动端 RTC 设备授权、业务审批、模型接入和并行验收修复不在此修复范围。

用户随后明确选择“正式桌面版自动认证，开发浏览器继续免配对”。实现沿用上述范围：`scripts/dev.mjs` 在桌面分支每次启动生成 32 字节随机值，传给 Web 服务并通过既有私有启动事件交给 Electron；`src/web-server.ts` 对桌面 `/api/` 在读取业务数据／请求体前检查凭据，使用常量时间比较；`packaging/electron/main.mjs` 只为当前主窗口、准确主 frame、正式根页面、准确本机 origin 的 API 请求添加请求头，任何请求已有的同名头均先剔除。预览、外站、其他窗口、来源缺失和网关退出后的请求不获得凭据；启动凭据缺失或格式错误时不加载会话。
