# HMR-CHAT-001：本机订阅聊天连接

流程来源：real-user-feedback，用户实际在 CLI 问候后无响应，收到 main_timeout；仅保留脱敏故障背景，不保存原始对话、账号或工具配置。测试输入来源：synthetic（通用问候和模拟本机配置）。

## 前置与步骤

1. 已有 Codex ChatGPT 登录；配置中可有其他 MCP，系统可能使用代理。
2. 指定自己的 codexHome，连接官方服务，不使用开发任务的临时 baseUrl。模型以账号 model/list 可用项为准。更换连接／模型时使用新的 runtime，保留旧数据。
3. 启动 Homer，发送通用问候，检查实际自然语言回复；仅“已启动”不算聊天可用。
4. 退出，确认子进程停止；本次不得复制凭据、修改全局 Codex/MCP/代理设置或创建 Worker。

## 预期和禁止

- 模型传输沿用显式代理环境；未配置时，在 macOS 使用已启用的 HTTP/HTTPS 系统代理；不转发其他应用环境秘密。
- 继承的 MCP 在 Homer 进程内明确禁用并核验；不生效时仍拒绝，不绕过检查。进程重启后租约记录必须更新。
- 账号认证继续由原 Codex 使用，不复制令牌。Worker 的命令网络权限不因此开放。
- 使用账号实际支持的模型，真实收到问候回复才记成功；端口可连接、HTTP 有响应和进程启动均不等于聊天成功。

## 入口、清理和局限

`npm test` 包含 tests/engine.test.ts 和 tests/proxy.test.ts 的离线检查，不调用模型。真实检查需显式运行 CLI 并发送通用问候，消耗订阅额度；不自动采集正文。清理只退出本次 CLI，不删除用户历史或修改系统设置。

2026-10-16 本机显式实测：Codex 0.154.0、Node 22.22.0，官方 ChatGPT 认证，账号 model/list 默认 gpt-6-astra；通用问候收到非空中文回复并正常退出。此前 gpt-6.1-sol 不在此账号返回列表、实际返回模型不可用。此项未重跑文件任务全链路，不代表其他账号或平台通过。
