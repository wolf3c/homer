# Homer 问题反馈

用户明确要求反馈即授权提交本次必要的脱敏摘要，不重复询问是否发送。先简短告知将向 Homer 团队发送问题摘要和必要环境信息，再执行；已有工具权限和审批仍有效，不自行绕过。

## 收集并整理

- Agent 自行判断需要哪些信息及工具，优先使用当前已知事实；必要时定向读取相关状态、日志或文档，不扫描无关目录或全部历史，不自动修复。
- 摘要说明现象、期望、已知操作步骤、影响和有依据的环境信息。区分用户描述、实际观察和原因推测；缺失项写“未知”，不编造版本、复现或原因。只有反馈对象或关键现象无法确定时才追问，不为填满模板打断用户。
- 区分手机端与主端，不把执行脚本的电脑环境当作手机环境。不得把第三方软件问题误投到 Homer。
- 只发送重新整理的脱敏摘要，不复制原始日志、完整对话、提示词、文件内容、工具参数/结果、凭据、个人信息或带查询参数的完整 URL。不收集联系方式，不截图、不上传附件、不启用自动采集。
- 不必要的敏感细节直接省略并注明证据缺失；确需扩大授权范围才询问。脚本只拦截部分明显敏感内容，不能代替 Agent 的隐私检查。TraceMind 服务端仍可能记录请求 IP 等网络信息，不宣称匿名。

## 提交

使用本 Skill 实际安装目录下的 `scripts/submit-feedback.mjs`，通过现有 Node 运行时执行。使用当前工具可用的 Node 路径，不硬编码开发机路径、不借用全局 Codex 配置。将 JSON 作为标准输入传入，不写临时报告文件、不把正文拼接进可执行代码或未转义的 shell 命令。

输入仅为 `{"title":"简短标题","body":"脱敏摘要"}`：标题非空且不超过 160 字符，正文非空且不超过 4,000 字符。文字较长时先压缩，保留事实，不静默截断。执行 `node --preserve-symlinks-main <Skill 实际目录>/scripts/submit-feedback.mjs`，避免 Node 解析入口路径时读取受保护的 HOME 父目录；不放宽文件权限。通过执行工具标准输入或带引号且与正文不冲突的 heredoc 传入 JSON，确保正文中的反引号和 `$()` 不会被执行。

接收地址及公开写入 projectKey 随脚本固定，不修改它们、不临时替换项目，不使用 `tracemind.submit_feedback`（它是开发者向 TraceMind 反馈的另一条通道），也不使用 MCP 管理 token。

## 结果

- 退出码 0 且返回 `ok: true` 和 `userFeedbackId`：简短告知已提交并保留反馈编号，不宣称问题已修复。
- `invalid_input` / `sensitive_content`：未发送；修正输入或脱敏后再提交。
- `not_configured`：未发送；说明 Homer 反馈渠道尚未配置，不自行创建项目或寻找其他凭据。
- `submission_rejected`：未获接收，说明提交被拒绝；不循环重试或修改固定目标。
- `delivery_unconfirmed`：可能已送达但没有可靠回执，说明结果未确认；不自动重发。用户再次要求发送时先告知可能重复。

不建立队列、后台重试或独立记录，当前对话中保留结果即可。网络或 Agent 不可用时，本 Skill 无法保证完成反馈。
