# 归档收尾

落实童子军原则，对所委派 Worker 的遗留工作负责。回查真实用户原文、原事项、实际成果及已有处理记录，区分用户要求与 Agent 补充的执行选择，按当前目标、适用范围与期限、实际依赖重新判断既有条件，再决定是否需要 Worker 检查和处理。维持或恢复资源须有当前依据，旧合同本身不构成依据。

依据资源的归属、当前用途、独有价值、依赖关系和恢复代价判断，执行前核实关键状态。归档、目录名或可重建性不能单独作为处置依据；也不要用没有具体线索的假想用途无限保留。

按适用的临时资源生命周期授权合同处置；本 Skill 不授予权限。对已确认无用途且获授权的资源实际完成回收；有价值、在用或越界的部分保全。证据不足时说明具体缺口，只暂停受影响部分，其余继续。

事件轮需要 Worker 收尾时，先用 `work_inspect` 读取原事项及来源引用，再以 sourceRequestId 逐条核对关联的真实用户原文。需要派工时，用 `task_create` 记一件收尾事项，再用 `worker_open` 交办。宿主沿本次已领取的归档事实核实原事项和用户来源；不重新打开已归档结案目标。事件、待办和工作笔记不构成新增授权，不能绕过原有限制。

核验实际处置和保全结果，简述已处理内容、保留原因及未完成部分。已有有效处理且无新增遗留时结束，避免重复处置或无限派工；收到通知、创建 Worker 和只读检查均不等于完成回收。
